## 현재 작업 순서 — 프론트엔드 Goal 분리

최신 사용자 요청에 따라 [FE Goal 계획](../../../TODO/FE_GOALS.md)의 Goal 2까지 구현했다. Goal 2는 기기 실행·원본 비교 검증 대기이며, 구현·자동 검증과 구분한다. 각 Goal은 사용자가 요청한 범위의 구현·테스트 작성·코드 검토·검증·기록 후 종료하고, 다음 Goal은 별도 요청으로 시작한다. 현재 Goal 3~13은 미착수다. 프론트엔드 단계에서 실제 Supabase·백엔드·인증을 연결하지 않는다.

## 전체 서비스 구현 순서 — 이전 기본안

1. **Supabase 설정 확인**: Data API·노출 옵션, 리전, 연결 방식, Auth 공급자·서명 키를 확인한다. 비밀 값은 저장소 밖에서 관리한다.
2. **첫 읽기 흐름 정의**: 피드 → 기사 상세 → 설명 수준 전환의 [화면 기본안과 근거](../../UXUI_AGENT/MEDIUM_REFERENCE.md)를 확보했다. 이 흐름에 맞는 최소 API를 정한다.
3. **프로젝트 초기화**: 호환 버전을 고정하고 Spring Boot·React Native 프로젝트와 필요한 검증 스크립트를 만든다. Expo 채택 여부도 이때 결정한다.
4. **읽기 기능 연결**: 콘텐츠·수준별 설명 스키마와 migration을 만들고, 목록·상세를 모바일까지 연결한다. 임시 데이터와 실제 RSS 콘텐츠를 구분한다.
5. **인증과 개인 기능**: Google 로그인, Spring JWT 검증, 프로필 초기화, 좋아요·북마크를 연결하고 권한·중복 요청을 검증한다.
6. **수집·생성 자동화**: 승인된 공급처의 RSS, AI 생성, 4단계 검증, 게시·재처리 흐름을 연결한다.
7. **정렬·조회수·배포**: 제품 정책을 정한 뒤 최신·인기·추천과 조회수를 완성하고, 두 모바일 플랫폼과 배포 환경을 검증한다.

이 순서는 기본안이다. 각 기능에 필요한 정책·계약을 정하면서 진행하고, 전체 문서나 전체 디자인 완성을 착수 조건으로 삼지 않는다.

현재 실행 범위에는 위 전체 서비스 작업을 한꺼번에 적용하지 않는다. 이번 프론트엔드 작업의 완료를 전체 서비스 MVP 완료로 기록하지 않는다.
