# 모바일 UI·접근성·플랫폼 규칙

[규칙 진입점](README.md) · [UX 기준](../../UXUI_AGENT/README.md) · [검증](TESTING_AND_DELIVERY.md)

## Medium 원본과 구현의 관계

- 기능에 해당하는 `medium/flows`의 분석 문서와 실제 이미지를 모두 확인한다. 문서만 읽고 이미지 비교를 완료했다고 하지 않는다.
- 앱·플랫폼·flow/screen ID·보관된 버전·검토일을 기록한다. 카탈로그 버전, 제품 빌드, PNG 크기, 논리 화면 크기, DPR을 구분한다.
- 배치, 글자 위계, 좌우/섹션 여백, 입력창, 이미지 비율, 구분선, 상태 피드백, 화면 전환을 대조한다.
- 모바일 폭에서 화면을 캡처하고 대응 원본과 나란히 확인한다. 위치 보정·크기 조정을 했다면 방법을 적는다. 서로 다른 콘텐츠를 픽셀 차이 수치 하나로 평가하지 않는다.
- 한글·자체 삽화·사실/AI 해석 구분·4단계 설명은 우리 서비스 요소다. 원본의 브랜드·글·사진을 제품 자산으로 복사하지 않는다.
- 범위에서 제외한 메뉴·반응·기능은 기록한다. 동작하지 않는 버튼을 원본에 있다는 이유만으로 추가하지 않는다.
- 기존 화면 전체의 디자인을 바꾸는 것은 별도 범위다. 현재 기능의 원본 충실도를 높이는 작업과 구분한다.

## 레이아웃·스타일·이미지

- 공통 색상·간격·타이포는 기존 token을 재사용한다. 기능 고유의 원본 수치는 기능 안에 둘 수 있으며, 같은 의미가 반복될 때 공통화한다.
- React Native의 논리 레이아웃 단위와 원본 이미지의 물리 픽셀을 구분한다. 이미지 픽셀을 그대로 여백·글자 크기로 넣지 않는다.
- `useWindowDimensions` 등 실제 가용 크기와 font scale 변화를 반영한다. 최초 기기 너비의 전역 상수로 회전·분할 화면·큰 글자를 고정하지 않는다.
- 화면마다 고정 폭을 쌓지 않는다. 본문 가독성을 위한 최대 폭, 좁은 화면의 최소 여백, flex 줄바꿈을 함께 설계한다.
- Safe Area의 책임을 화면·navigator·고정 바 중 어디에서 처리하는지 정한다. 상태 표시줄·노치·홈 인디케이터·시스템 바 여백을 이중 적용하지 않는다.
- 고정 반응 바와 하단 메뉴가 마지막 문단·키보드·조작 버튼을 가리지 않게 한다. 콘텐츠 하단 여백은 실제 바와 inset을 기준으로 한다.
- 동적 제목·오류 문구를 고정 높이로 잘라내지 않는다. 썸네일 같은 의도적인 비율 영역과 텍스트의 자연 높이를 구분한다.
- 이미지 없음, 로딩, 실패를 구분한다. 없는 이미지에 의미 없는 빈 상자를 남기지 않고, 이미지 실패가 글 읽기를 막지 않게 한다.
- `cover/contain`·SVG 비율·crop 위치를 실제 화면으로 확인한다. 설정한 박스 크기와 보이는 이미지 크기가 같다고 추정하지 않는다.
- 장식 이미지와 정보를 전달하는 이미지의 접근성을 구분한다. 사진 설명·출처가 필요한 경우 실제 콘텐츠와 일치시킨다.
- z-index·overflow·터치 전달·그림자는 iOS/Android와 웹 결과가 다를 수 있다. 웹에서 글자나 버튼이 가려지는 문제도 별도 확인한다.
- 현재 밝은 테마를 유지한다. 다크 모드를 승인받아 추가할 때는 토큰·시스템 바·이미지·비활성/오류 대비를 함께 검증한다.

## 입력·폼·키보드

- 입력의 label·필수 여부·오류·도움말을 연결한다. placeholder만으로 항목의 의미를 설명하지 않는다.
- 한글 조합, 붙여넣기, 이모지, 긴 입력, 지우기, 커서 이동을 고려한다. 실제 기기의 IME 확인 여부를 기록한다.
- 키보드 종류, 자동 대문자·자동 수정, 엔터/검색/완료 행동은 필드 의미에 맞게 정한다. SDK 버전에서 지원하는 prop을 확인한다.
- 입력 중 정규화 때문에 커서를 끝으로 보내지 않는다. 화면 원문과 제출/검색용 값을 분리한다.
- 키보드 회피, 스크롤, safe inset과 고정 버튼의 책임을 중복 적용하지 않는다. 키보드가 열린 상태에서 마지막 입력·오류·제출 버튼에 도달할 수 있어야 한다.
- autofocus는 명확한 사용자 진입 의도가 있을 때만 사용한다. 목록 복귀·tab 재선택·갱신 때문에 키보드가 다시 열리지 않게 한다.
- 입력창을 매 입력마다 remount하지 않는다. 조건 분기·key 변경으로 focus와 선택 영역을 잃는지 확인한다.
- 화면 이동 전 keyboard dismiss가 필요한지 정한다. 목록의 탭이 키보드를 닫기만 하는지, 첫 탭부터 항목을 선택하는지 일관되게 한다.
- 제출 중 입력을 막을지, 수정 내용을 다음 제출로 보관할지 정한다. 실패하면 사용자의 입력을 보존하고 수정 가능한 원인을 설명한다.
- 문자 수 제한의 기준(코드 단위/글자/서버 제한)은 실제 계약에서 확인한다. UTF-16 길이를 사람이 인지하는 글자 수와 항상 같다고 보지 않는다.

## 접근성

프로젝트의 기본 터치 목표는 양 플랫폼에서 **48×48 이상 논리 단위**다. 원본 아이콘·회색 검색 면은 더 작을 수 있지만 조작 영역을 확보한다. 이는 이 프로젝트의 기준이며 각 OS의 최소 요구값을 인용한 것이 아니다. 인접한 hit 영역이 겹치거나 부모 경계 밖의 hitSlop에만 의존하지 않게 확인한다.

- 의미에 맞는 role과 한글 label을 제공한다. 선택·체크·비활성·처리 중 상태를 실제 화면과 일치시킨다. 색상만으로 상태를 구분하지 않는다.
- 카드 전체 이동과 내부 좋아요 버튼처럼 별도 행동은 접근성·터치 경계를 분리한다. 버튼 안에 버튼을 중첩하고 이벤트 전파 차단만으로 해결하지 않는다.
- 그룹에 `accessible`을 무조건 켜서 자식 조작 요소를 숨기지 않는다. VoiceOver와 TalkBack의 탐색 순서·묶임을 각각 확인한다.
- 상태 변경·오류를 필요한 범위에서 알린다. 매 키 입력·자동 갱신마다 중복 안내해 읽기를 방해하지 않는다.
- 모달을 열면 관련 제목/행동으로 focus를 안내하고 닫으면 원래 조작 위치로 복귀한다. 가려진 배경이 계속 읽히거나 눌리지 않는지 확인한다.
- 기본 글자 확대를 유지한다. 본문·버튼을 맞추려고 `allowFontScaling={false}`를 일괄 적용하지 않는다. 로고 같은 비정보성 장식의 예외는 구분한다.
- 큰 글자에서 텍스트와 이미지의 세로 배치, 줄바꿈, 스크롤을 우선한다. 정보가 잘리는 `maxFontSizeMultiplier` 제한은 근거와 대체 접근 방법 없이 추가하지 않는다.
- 애니메이션 감소 설정, 색 대비, 키보드/보조 입력 탐색을 검토한다. 애니메이션·햅틱만으로 성공을 전달하지 않는다.

접근성 prop의 의미와 플랫폼 차이는 [React Native 0.86 접근성 문서](https://reactnative.dev/docs/0.86/accessibility)를 대조한다. DOM의 ARIA 동작을 확인한 결과만으로 VoiceOver/TalkBack 검증을 대체하지 않는다.

## Navigation·뒤로 가기·복원

- 현재 native-stack과 bottom-tabs 구성을 유지한다. router를 병행 도입해 이동 상태를 두 군데에서 관리하지 않는다.
- 경로 타입을 정의하고 ID·검색 조건·진입 맥락처럼 최소한의 직렬화 가능한 정보를 전달한다. 기사 객체 전체·함수·token을 params에 넣지 않는다. [React Navigation params](https://reactnavigation.org/docs/params/).
- 같은 기사 ID가 다른 탭에서 열릴 때 경로 재사용·진입 맥락·뒤로 가기 label이 맞는지 확인한다. `push`, `navigate`, `replace`, reset의 차이를 의도에 맞게 사용한다.
- 상세에 진입해도 원래 목록의 검색어·정렬·조회 페이지·스크롤을 보존한다. 복원 정책과 cache 보관 정책을 함께 검토한다.
- mount/unmount와 focus/blur를 같은 사건으로 보지 않는다. focus에서 필요한 구독만 켜고 정리하며 중복 listener를 만들지 않는다.
- Android 시스템 뒤로 가기는 현재 route·모달·편집 상태가 실제로 소비할 때만 처리한다. 처리하지 않으면 navigation/OS에 맡긴다. BackHandler는 열린 native Modal에서 이벤트를 발행하지 않는 제약이 있으므로 모달의 닫기 경로도 따로 확인한다. [RN BackHandler](https://reactnative.dev/docs/0.86/backhandler).
- iOS 스와이프 복귀·중간 취소, Android 시스템 뒤로 가기/제스처와 지원 환경의 predictive back을 확인한다. JS 모의 이벤트를 기기 제스처 검증으로 기록하지 않는다.
- 브라우저 툴바 뒤로 가기·URL linking과 앱 안의 뒤로 가기는 별개다. 웹 linking을 도입하지 않은 미리보기에 동일한 동작을 보장한다고 쓰지 않는다.
- process 재생성 후 복원은 별도 설계다. mounted된 탭의 메모리 보존을 앱 재실행 복원으로 표현하지 않는다.

## 플랫폼별 확인과 native 경계

| 영역 | iOS 확인 | Android 확인 |
| --- | --- | --- |
| 화면 가장자리 | 상태 표시줄·노치·홈 인디케이터·회전 | edge-to-edge·상태/내비게이션 바·디스플레이 컷아웃 |
| 글자·입력 | Dynamic Type·VoiceOver·키보드·복사/선택 | 글자/화면 크기·TalkBack·IME·자동 입력 |
| 이동 | 스와이프 복귀·모달 닫기·중간 취소 | 시스템/제스처 뒤로·모달·Activity 재생성 |
| 생명주기 | inactive/background·복귀·외부 인증 취소 | background·다른 Activity·process 재생성·복귀 |
| 외부 기능 도입 시 | 권한 설명·거절·설정 복귀·entitlement | runtime permission·거절·설정 복귀·manifest |

이 표는 확인할 조건이다. 실제 지원 OS 최소 버전·target SDK·권한은 설치된 패키지와 빌드 설정으로 확인한다. 문서에 임의의 최신 버전을 고정하거나 미래 심사 요건을 현재 구현 사실로 적지 않는다.

- 공통 코드로 표현할 수 있는 차이는 작은 adapter/prop으로 처리한다. 동작 구조 자체가 다르면 `.ios.tsx`·`.android.tsx`로 분리하되 같은 공개 계약을 유지한다.
- 웹에서만 필요한 처리는 제한된 경계에 둔다. 제품 화면을 DOM 전용 API에 의존하게 만들지 않는다.
- 외부 링크·deep link는 허용 scheme·host·경로·입력 길이를 확인한다. 식별자만으로 권한이 증명되지 않는다. 잘못된 링크·없는 자원·이미 열린 화면·cold/warm start를 구분한다.
- native module 도입은 JS 설치 완료와 다르다. Expo 개발 빌드, 현재 RN 아키텍처·엔진 호환, autolinking/config plugin, Swift/Kotlin 의존성, 빌드·설치까지 확인한다.
- 직접 native 코드를 작성할 때 UI thread의 작업 범위, 비동기 결과를 반환할 JS 수명, 취소·중복 완료·listener 해제·메모리 소유권을 정한다. 한 플랫폼 성공을 다른 플랫폼 구현으로 간주하지 않는다.
- 플랫폼 코드·설정의 설명 주석도 [한글 주석 규칙](CODE_CONVENTIONS.md)을 따른다.
