# React Native iOS·Android 개발 규칙

개정일: 2026-11-18 KST

20년차 모바일 엔지니어에게 요구되는 설계·구현·장애 대응·검증 책임을 이 프로젝트의 실행 규칙으로 정리한다. 담당자는 화면 구현뿐 아니라 상태의 소유권, 비동기 작업의 결과, 플랫폼 차이, 접근성, 성능, 배포 후 호환성까지 설명할 수 있어야 한다. 문서가 있다는 이유만으로 기존 코드가 모든 기준을 충족한다고 간주하지 않는다.

## 적용 범위와 우선순위

1. 최신 사용자 지시와 이미 승인된 범위를 먼저 따른다. 일상적인 구현 선택에 형식적 승인을 추가하지 않는다.
2. 현재 작업 범위는 [FE Goal 계획](../../../TODO/FE_GOALS.md), 구현 상태는 [현재 상태](../COMMON/IMPLEMENTATION_STATUS.md)와 실제 코드로 확인한다.
3. 이 폴더는 프론트엔드 설계·작성·검토 기준이다. [프로젝트 범위](../../PROJECT_SCOPE.md), [UX 규칙](../../UXUI_AGENT/README.md), [공통 검증 규칙](../COMMON/QUALITY_AND_WORKFLOW.md)과 함께 적용한다.
4. 과거 문서의 하단 메뉴 3개·검색 제외·Expo 도입 검토 문구보다 현재 승인된 4개 메뉴·검색·Expo 기반 구현을 우선한다. 제품의 새 정책을 이 규칙에서 임의로 확정하지 않는다.

**현재는 fixture·mock을 사용하는 프론트엔드 단계다.** 백엔드·실제 Supabase·실제 인증·RSS·AI는 연결하지 않는다. 이 문서의 인증·네이티브 연동·출시 규칙은 해당 작업이 승인될 때 적용하는 기준이다. 문서 작성 자체로 Goal 7이나 후속 기능을 시작하지 않는다.

제품 대상은 iOS·Android다. 사용자 요청으로 추가한 PC 브라우저는 개발용 미리보기이며 그대로 보존한다. 웹에서의 동작 확인과 네이티브 검증을 구분한다.

## 반드시 지킬 공통 기준

- 화면은 표현과 사용자 행동 연결을 맡는다. HTTP, 인증 갱신, 저장소 파싱, 여러 화면의 상태 동기화를 한 화면에 모으지 않는다.
- 같은 사실의 기준 상태는 한 곳에서 관리한다. 홈·검색·상세가 같은 기사의 반응을 각각 독립적으로 수정하지 않는다.
- 정상 응답뿐 아니라 취소·지연·응답 역전·실패·복귀·재진입을 설계하고 검증한다.
- 사용자 입력이 바뀌었을 때 이전 결과를 보여줄지, 유지하면서 갱신할지를 명시한다. 서로 다른 선택과 본문을 같은 상태처럼 표시하지 않는다.
- iOS·Android를 각각 확인한다. 브라우저·Jest·JS 번들 성공을 실제 기기·네이티브 빌드 성공으로 기록하지 않는다.
- Medium의 배치·타이포·여백·상태 표현을 실제 이미지로 대조한다. 원본 관찰, 우리 서비스의 추가 요소, 제외 범위를 구분한다.
- 새로 작성하거나 수정하는 **설명 주석은 한글 한 문장·한 줄**로 작성한다. 코드 식별자·도구 지시문·공급자 원문을 임의로 번역하지 않는다. 세부 예외와 예시는 명명 규칙을 따른다.
- TypeScript strict, 상태별 타입, 접근 가능한 조작, 실패 복구를 유지한다. `any`·타입 단언·lint 무시로 결함을 덮지 않는다.
- 필요한 만큼 구조화한다. 사용되지 않는 계층·추상화·전역 저장소·의존성을 숙련도의 증거로 추가하지 않는다.
- 기존 사용자 변경, 실행 중인 미리보기, ENV, 참고용 `medium/flows`를 보존한다. 커밋·push·배포는 해당 지시가 있을 때 수행하며 이전 요청을 새 변경에 대한 자동 승인으로 확대하지 않는다.

## 현재 코드 기준선

아래는 개정일의 [package.json](../../../FE/package.json)·[tsconfig](../../../FE/tsconfig.json)·[앱 코드](../../../FE/src/app/navigation/AppNavigator.tsx)를 확인한 기록이다. 최신 버전을 뜻하지 않으며 실제 작업 시 다시 확인한다.

| 항목 | 현재 구현 |
| --- | --- |
| 앱 | Expo 57.0.33, React 19.2.3, React Native 0.86.3 |
| 이동 | React Navigation native-stack + bottom-tabs. Expo Router 미사용 |
| 타입 | TypeScript strict, `noUncheckedIndexedAccess`, 파일명 대소문자 일치 검사 |
| 데이터 | 기능별 source 함수·fixture·hook. 실제 서버 client 없음 |
| 상태 도구 | TanStack Query·Redux·Zustand 미설치. 도입은 필요한 문제와 비용을 검토한 후 결정 |
| 검사 | npm, ESLint, Jest의 iOS/Android 설정, React Native Testing Library 14 |
| 미리보기 | 동일 화면 코드를 React Native Web으로 실행 |

문서의 예시는 명명·경계 설명용이며 신규 기능이나 실제 API 구현을 뜻하지 않는다. 새 규칙을 맞춘다는 이유로 모든 기존 파일을 이동하거나 영문 주석을 일괄 수정하지 않는다. 해당 작업에서 다루는 코드에 적용하고, 범위를 벗어난 차이는 검토 기록에 남긴다.

## 설계 결정과 예외 기록

기능 작업의 결과 문서에 다음을 간결하게 기록한다. 작은 변경에 별도의 거대한 설계 문서를 강제하지 않는다.

| 항목 | 기록 내용 |
| --- | --- |
| 문제·사용자 흐름 | 어떤 행동과 실패를 해결하는가 |
| 상태·수명 | 소유자, 식별 키, 화면 이탈·재진입·앱 재실행 시 동작 |
| 선택과 근거 | 현재 요구에 맞는 방식, 다른 선택의 비용, 중요한 제약 |
| 임시 기본안 | fixture 정책과 실제 서버 정책의 구분 |
| 검증·한계 | 실행한 명령·환경·결과, 원본 차이, 미검증 범위 |
| 예외 | 적용하지 않은 규칙, 이유, 영향, 다시 검토할 조건 |

예외가 있다는 사실만으로 사용자 승인을 다시 요구하지 않는다. 이미 승인된 범위에서 해결 가능한 문제는 처리한다. 제품 의미·개인정보·외부 연결·비가역 작업처럼 실제 결정이 필요한 사항만 구체적인 결과와 함께 확인한다.
