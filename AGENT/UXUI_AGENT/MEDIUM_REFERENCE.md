# Medium 모바일 참고 조사

최초 조회일: 2026-11-17 · 후속 조사 안내 갱신: 2026-11-18

이 문서는 선택 화면 10장을 조사한 당시의 기록과 구현 기본안이다. 후속 조사에서는 Medium iOS Latest의 63개 흐름·273개 단계 참조·고유 화면 200장을 분석하고 R2 재검토했다. 현재 범위는 [전체 분석](../../medium/README.md)과 [누락·내용 재검토](../../medium/REVIEW_R2.md)를 따른다. 아래 10장·4개 흐름 수치는 최초 조사 이력이며 현재 전체 조사 수치가 아니다.

## 확인 범위

- 참고 앱: [Medium iOS](https://gummble.com/apps/medium-ios), 앱 식별자 `medium-ios`.
- `gummble_get_app` 결과: `Latest` 버전 ID `1419`에 200장, 과거 버전까지 합하면 5개 버전 569장이다. 첫 페이지의 화면 메타데이터 12개만 조회했다.
- 흐름 검색 결과 6개를 확인했다. 그중 Home·Library·Logging in·Profile의 순서 있는 화면 참조 22개를 조회했다. 흐름 사이에 같은 홈 화면이 반복된다.
- 화면 상세 도구로 선택한 서로 다른 화면 10장을 받아 실제 이미지를 확인했다. 전체 200장이나 569장을 확인한 것은 아니다.
- Gummble의 `Latest` 표기를 현재 배포된 Medium 앱 버전과 동일하다고 간주하지 않는다. 개별 흐름·검색 결과의 버전은 별도로 검증하지 않았다.
- 이번 근거는 Gummble의 iOS 캡처와 도구 응답이다. 실제 Medium 앱 조작, Android 화면, 원본 코드·디자인 토큰은 확인하지 않았다.
- MCP 로그인과 인증된 조회가 성공했다. 현재 대화에 직접 노출되지 않은 도구는 같은 인증을 사용하는 로컬 Codex app-server 경유로 호출했다. 추가 모델 실행은 하지 않았다.

## 1차 MVP에 적용할 기본안

Medium 하나로 첫 읽기 흐름을 설계하기에 충분하다. 다음은 위 관찰을 바탕으로 한 우리 앱의 제안이며, Medium의 실제 기능이나 사용자 확정 정책과 구분한다.

| 우리 화면 | 구성 기본안 |
| --- | --- |
| 홈 | 상단 최신·인기·추천 탭 → 제목·짧은 설명·출처·시각·선택적 썸네일을 가진 기사 목록 |
| 기사 상세 | 제목·출처·시각 → 설명 수준 선택 → 사실 요약 → 코스톨라니 철학을 참고한 AI 해석 → 수준별 예시 → 출처 링크 |
| 설명 수준 | `초등학생 / 중학생 / 고등학생 / 성인` 선택 컨트롤. 현재 선택을 표시하고 같은 기사의 설명·예시를 변경 |
| 북마크 | 저장한 기사 목록에서 상세로 이동, 저장 해제. 저장한 글이 없으면 홈으로 이동할 수 있는 안내 |
| 로그인 | 서비스 소개와 Google 로그인 버튼. 취소·실패 안내 및 성공 후 원래 화면 복귀 |
| 내 정보·설정 | 최소 프로필, 설명 수준 설정, 로그아웃을 후보로 구성. 계정 정책에 필요한 항목은 별도 결정 |

- 하단 메뉴는 **홈 · 북마크 · 설정** 3개를 제안한다. Medium 캡처의 홈·탐색·라이브러리·프로필 4개를 그대로 옮기는 결정은 아니다.
- 목록의 선택 탭 모양은 참고하되 `For you / Following / Featured`의 의미를 우리 최신·인기·추천 정책으로 대체한다. 정렬 알고리즘은 아직 미정이다.
- 기사 상세 하단에 좋아요·북마크를 두는 안을 제안한다. Medium의 박수 반응 방식·댓글·공유 기능까지 자동으로 도입하지 않는다.
- 사실 요약과 AI 해석은 제목과 문단 구획으로 구분한다. 일반적인 영향 경로를 설명하고 실제 코스톨라니의 발언처럼 표현하지 않는다.
- 4단계 설명 선택은 우리 앱이 추가하는 컨트롤이다. 실제 나이를 입력받는 가입 절차로 확장하지 않는다. 초기 선택값과 저장 위치는 구현 시 정한다.
- 기본 시각 방향은 밝은 배경, 강한 제목 대비, 여유 있는 문단 간격, 얇은 구분선이다. 정확한 폰트·크기·행간은 한글과 글자 확대를 적용해 기기에서 검증한다.

## 첫 구현과 검증 범위

첫 화면 작업은 **홈 → 기사 상세 → 설명 수준 전환** 순서로 한다. 백엔드·React Native 초기화와 최소 읽기 API 설계에 사용할 자료가 확보됐다.

1. 임시 콘텐츠임을 구분할 수 있는 데이터로 목록·상세·4단계 표현을 먼저 연결한다.
2. iOS·Android에서 긴 제목, 이미지 없는 기사, 긴 본문, 글자 확대, 뒤로 가기와 화면 가장자리 안전 영역을 확인한다.
3. API 연결 후 로딩·빈 결과·실패·재시도, 수준 변경 실패, 반응 저장 실패를 확인한다.
4. Google 인증과 좋아요·북마크를 연결한 뒤 읽던 글로 복귀하고 저장한 글을 다시 찾는 흐름을 검증한다.

캡처에서는 인증 취소·실패, 오프라인, 네트워크 오류, 실제 스크롤·전환 동작을 검증하지 않았다. 해당 동작은 구현과 함께 확인한다. 비로그인 접근 범위, 조회수·정렬 정책, 계정 정책도 기존 제품 문서의 미정 상태를 유지한다.
