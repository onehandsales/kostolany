# 모바일 UX 규칙

## 기준

1차 MVP의 중심은 금융 콘텐츠를 찾고 읽고 저장하는 경험이다. 참고 제품은 **Medium 모바일**이다. 2026-11-17 선택 화면 10장 조사에 이어, 2026-11-18 Gummble의 Medium iOS Latest 63개 흐름·273개 단계 참조·고유 화면 200장을 분석하고 R2 재검토했다. [전체 분석](../../medium/README.md)과 [재검토 결과](../../medium/REVIEW_R2.md)에 현재 확인 범위를 기록한다. [최초 조사와 적용 기본안](MEDIUM_REFERENCE.md)은 당시 관찰과 제안의 이력이다. 실제 계정·기기 동작은 재현하지 않았다.

CRM 프로젝트의 화면 구조나 제품 기준을 이 앱에 적용하지 않는다. 모의투자 기능을 나중에 도입할 수 있다는 이유로 지금 차트·주문·지갑 탭을 미리 넣지 않는다.

## 화면 조사 방법

- 자료의 플랫폼이 iOS·Android인지 확인한다. 모바일 관련 회사의 웹사이트 화면을 모바일 앱 화면으로 분류하지 않는다.
- Gummble 캡처, 실제 Medium 앱 관찰, 공식 자료, 자체 제안을 구분한다.
- 확인한 자료에는 앱·플랫폼·화면명·조회일·원본 링크 또는 도구 식별자를 기록한다.
- 도구에 연결하지 않았거나 유료 화면을 보지 못했다면 확인했다고 쓰지 않는다.
- 구조와 상호작용을 참고하되 Medium의 브랜드·글·사진을 서비스 자산으로 그대로 사용하지 않는다.
- 전체 디자인 시스템이나 별도 디자인 파일 완성을 코드 작업의 필수 선행 조건으로 두지 않는다. 실제 근거가 있는 최소 화면부터 구현할 수 있다.

## 필요한 화면과 상태

| 화면 | 필요한 기능·상태 |
| --- | --- |
| 피드 | 최신·인기·추천 전환, 콘텐츠 카드, 로딩·빈 결과·재시도·다음 페이지 |
| 기사 상세 | 제목·출처·시각, 공통 사건 설명, 수준별 해석·예시, 좋아요·북마크 |
| 설명 수준 선택 | 초등학생·중학생·고등학생·성인 4단계, 현재 선택, 변경 후 본문 동기화 |
| 북마크 | 저장한 콘텐츠, 저장 해제, 빈 상태, 로그인 상태에 따른 처리 |
| 로그인 | Google 로그인, 취소·실패·완료 후 원래 흐름 복귀 |
| 내 정보·설정 | 필요한 최소 프로필·설명 수준·로그아웃 등; 구체 범위는 구현 전 결정 |

하단 메뉴는 홈·북마크·설정 구성을 기본 후보로 검토하되, 실제 Medium 모바일 자료와 필요한 화면 흐름을 확인한 후 고정한다. 검색·알림·댓글 같은 미합의 기능을 기본 화면에 추가하지 않는다.

## 읽기 경험

- 카드에서 제목과 주제, 출처·시간 등 판단에 필요한 정보를 빠르게 읽을 수 있게 한다.
- 상세에서 사실 요약과 AI 해석을 시각적으로 구분한다.
- “코스톨라니가 이렇게 말했다”는 표현 대신 철학을 참고한 해석이라는 의미를 전달한다.
- 같은 사건을 설명 수준에 맞춰 풀어주고 각 수준에 예시를 제공한다. 수준 변경이 실제 투자 관점이나 사실을 바꾸는 것으로 보이지 않게 한다.
- 설명 수준은 독자가 선택하는 난이도로 다룬다. 나이 입력이나 학교 정보를 기본 가입 조건으로 추가하지 않는다.
- 본문 폭·행간·문단 간격·글자 크기는 작은 화면에서 긴 글을 읽는 상황으로 검증한다.
- 서버 저장 실패, 로그인 만료, 오프라인에서도 사용자가 다음 행동을 이해할 수 있게 한다.

## 1차 UX 검증

처음 들어온 사용자가 콘텐츠 하나를 찾아 읽고, 설명 수준을 바꾼 후 저장한 콘텐츠를 다시 찾을 수 있는지 확인한다. 추천 알고리즘·조회수 계산 등 구현 정보를 일반 화면에 설명하지 않고, 사용자 판단에 필요한 출처·시각·해석 성격을 보여준다.
