# 제품 범위와 결정

기준일: 2026-11-17

## 제품의 중심

해외 금융·경제 뉴스를 읽고, 그 사건이 경제와 자산에 어떤 경로로 영향을 줄 수 있는지 이해하는 모바일 콘텐츠 앱을 만든다. 사용자가 직접 읽을 만한 서비스를 운영하면서 Kotlin/Spring Boot의 설계·테스트·운영 경험을 쌓는다.

1차 제품의 중심은 콘텐츠 탐색과 읽기다. 모의투자는 1차 완성 후 도입 여부부터 다시 결정한다.

## 확정한 1차 범위

| 항목 | 범위 |
| --- | --- |
| 플랫폼 | React Native 기반 iOS·Android 앱. 사용자용 웹은 만들지 않는다. |
| 수집 | 해외 금융·경제 RSS를 활용한다. 초기 공급처와 수집량은 미정이다. |
| 콘텐츠 | 기사 사실 요약 + 코스톨라니의 투자 철학을 참고한 AI 해석 |
| 설명 수준 | 초등학생·중학생·고등학생·성인 수준 4가지. 각 수준에 맞는 예시 포함 |
| 로그인 | Google 로그인. 현재 인증 구성 방향은 Supabase Auth 사용 |
| 반응 | 좋아요, 북마크, 조회수 |
| 피드 | 최신순, 인기순, 추천순 |
| UX 참고 | Medium 모바일. 화면 조사에는 사용자가 선택한 Gummble 활용 예정 |
| Backend | Kotlin + Spring Boot |
| 데이터·파일 | Supabase PostgreSQL + Storage |
| 트랜잭션 | Spring 코드에서 `@Transactional`로 업무 DB 트랜잭션 관리 |

책의 기준은 사용자가 지정한 『돈, 뜨겁게 사랑하고 차갑게 다루어라』 1~3권이다. 책 원문·발췌·독서 노트는 아직 제공되거나 검증되지 않았다. 내용을 이미 학습했다고 기록하지 않는다.

## 콘텐츠 구성 기본안

하나의 뉴스 사건에 공통 사실과 출처를 두고, 설명 수준별로 표현과 예시를 바꾼다.

1. 무슨 일이 있었는가: 출처에 있는 사실과 발표 시점.
2. 왜 주목할 만한가: 확인된 배경과 추론의 구분.
3. 어떤 경로로 영향을 주는가: 예금·대출·주식·부동산 등에 관한 일반적인 시나리오.
4. 코스톨라니의 철학을 참고하면 어떤 점을 살필 수 있는가.
5. 선택한 설명 수준에 맞는 생활 예시와 짧은 정리.

이는 실제 코스톨라니가 해당 사건에 대해 발언하거나 예측했다는 뜻이 아니다. 사실, 인용, AI의 해석을 구분한다. 뉴스에 없는 원인을 확정하거나 수익·가격 방향을 보장하는 문장을 생성하지 않는다.

4단계는 설명 난이도다. 사용자의 실제 나이 수집, 연령 인증, 어린이 대상 서비스 운영 정책을 확정한 것으로 해석하지 않는다. 사용자가 난이도를 직접 선택하는 것이 기본안이다.

## 1차에서 만들지 않는 기능

- 모의계좌, 가상 현금, 주문·체결, 실시간 시세·차트, 실제 투자계좌 연결.
- 사용자의 재산·보유 종목·대출 정보를 수집하는 맞춤 자산 분석.
- 영어 학습, 문제 풀이, 점수·시험 기능.
- 사용자 글쓰기, 댓글·팔로우·채팅, 유료 구독, 별도 관리자 웹.

위 기능이 필요해지면 사용자와 범위를 다시 정한다. 이를 대비한다는 이유로 1차에 주문·지갑·교육 테이블을 미리 만들지 않는다.

## 구현 전에 정할 정책

| 정책 | 아직 정하지 않은 부분 |
| --- | --- |
| RSS | 공급처, 이용 가능한 데이터 범위, 수집 주기·양, 중복 판정 기준 |
| 생성 | 모델·비용 한도·재시도 횟수, 게시 조건, 기존 콘텐츠 재생성 방식 |
| 인기순 | 계산 기간, 점수에 포함할 반응과 가중치 |
| 추천순 | 관심사·읽기 기록 사용 여부, 초기 사용자 기본 추천 |
| 최신순 | 정렬 기준 시각과 같은 시각의 순서 |
| 조회수 | 조회로 인정할 조건, 중복 제외 단위·기간 |
| 접근 | 비로그인 읽기 허용 범위, 로그인 유도 시점 |
| 계정 | 프로필 초기화, 탈퇴·데이터 보존, 다른 로그인 수단 필요 여부 |
| 배포 | 백엔드 호스팅, 모바일 빌드 도구, 스토어 배포 방식 |

정책은 해당 기능 구현 전 필요한 만큼만 결정한다. 사용자에게 보이는 의미를 임의로 정하거나, 인기순을 추천순으로 이름만 바꾸어 제공하지 않는다.

## 1차 완료 판단

- 실제 RSS의 뉴스가 출처를 가진 콘텐츠로 저장되고, 4단계 설명과 예시를 읽을 수 있다.
- Google 로그인 후 본인의 좋아요·북마크를 저장하고 다시 조회할 수 있다.
- 합의한 기준대로 최신순·인기순·추천순과 조회수가 동작한다.
- iOS와 Android에서 읽기·로그인·반응·오류 복구 흐름을 검증한다.
- 핵심 API 권한, DB 원자성, 중복 요청, 생성 실패·재처리를 검증한다.
- 로컬 데모, 실제 외부 연동, 배포, 스토어 심사·출시는 각각 별도 상태로 기록한다.

개발 기간은 빠른 1차 완성을 목표로 한다. 사용자의 “1주일 정도” 예상은 검증이나 스토어 심사가 끝났다는 의미가 아니다.
