### 선택 복원과 사진 끝의 입력 판정

1. `RichBody`의 포커스 복원을 focus→setSelection 순서로 수정했다. 설치된 enriched-html1.2.0의 Android `requestFocusProgrammatically()`는 `setSelection(selection.start)`를 호출해 범위를 접는다. 기존 setSelection→focus 순서는 굵게/Redo 후 선택이0으로 접히는 원인이었다.
2. 사진으로 끝나는 연속 입력의 native 텍스트는 마지막 빈 행1개를 생략한다. 앞선 작업은 HTML 재주입 반복만 막았고, 텍스트/선택 이벤트는 여전히 다르다고 판단해 조합 잠금·선택 무시가 남았다. 동일 문서 판정을 정규화·조합 여부·선택 수신에 함께 적용했다. 마지막 사진 바로 뒤 한 행의 생략만 허용하며 실제 문장 변경과 중간 사진 경계의 정규화는 유지한다.
3. 순서 수정 검증 중 사진 모드 전환에서 오래된 접힌 커서와 실제 선택 범위가 엇갈려 일반 문단에 italic이 붙는 현상을 발견했다. 실제 native 범위/텍스트가 현재 접힌 커서와 일치할 때만 입력 서식을 동기화하도록 보완했다. 단순히 순서만 바꾼 중간 버전은 최종 결과가 아니다.

기존 코드에서 실패하는 회귀 사례를 먼저 확인했다. 선택 보완 후 타입 검사·변경4개 TS/TSX lint·관련18 suites/118 tests가 iOS/Android Jest 설정에서 통과했다(74.435초, 실패/skip0). 이후 부제 색상만 최종 픽셀값으로 조정하고 타입/해당 파일 lint·실제 다크 brain120%를 다시 확인했다. 구현 PNG의 제목/부제 주요 글자색도#ffffff/#e6e7e6이었다. 최초 검사 명령의 존재하지 않는 파일 경로는 수정한 뒤 실제 파일9개로 최종 실행했다. 중간 실행 수를 합산하지 않으며 Jest iOS 설정을 실제 iOS 실행으로 표시하지 않는다.

[Android 실행 기록](FE_MOBILE_EXECUTION_01_RESULT.md#dark-selection-native-20261127)에서 일반 혼합 본문0..26과 사진 포함0..28의 굵게/Undo/Redo, Cut/Undo·커서 입력·초안 재개를 구분한다. 모드 진입 자체는 선택을 다시 시작하는 동작이며 기존 범위의 모드 간 유지까지 완료로 확대하지 않는다.

### 읽기 사진 경계 판정과 다음 작업

`Highlighting a phrase`02와 `Responding to a phrase`01은 같은 텍스트 선택 캡처이며, 여러 줄에 걸친 한 문단 선택과 Highlight/Respond/Share를 확인할 수 있다. 사진을 가로지르는 선택 결과·복사 내용·하이라이트 앵커 정책은 이 자료로 확인되지 않는다. 현재 `publishedSelection.ts`는 이미지/구분선을 selectable:false로 만들고 `selectionDocument.passageAt`은 이를 통과한 범위를 거절한다. 텍스트 인용의 정확한 원문/버전 검증을 무시하도록 바꾸지 않았다. 읽기 사진 경계 연속 선택은 미지원, 원본의 해당 지원 여부는 미확인으로 구분한다.

다음은 원본이 있는 상태의 세부 배치/Follow 윤곽·메타데이터/캡션 간격과 나머지 화면의 시각 잔여를 정리하는 일이다. 원본 서체0개·인용선18dp·사진 선택 모드 여백·가려진 자산·읽기 사진 경계·실제 iOS/실기기·전수 판정·요구사항/DB/API는 남는다. 기존31개 기능 검사를 다시 요청하지 않으며 사용자 확인 대기 항목을 추가하지 않는다.

[공식 입력 API](https://docs.swmansion.com/react-native-enriched-html/api-reference/enriched-text-input/)도 확인했다. 입력 전체를 이동하면 일반 문단/사진도 이동하고, 문단별로 입력을 나누면 기존 연속 선택 구조가 달라지므로 적용하지 않았다. Android 입력의 줄 나누기는 설치된 `EnrichedTextInputView`/`MeasurementStore`에서 HIGH_QUALITY로 고정되어 있다. Swift/Kotlin·라이브러리 소스·새 폰트/패키지는 수정하지 않았다.

### 배치 검증 중 발견해 함께 수정한2개 결함

1. 빈 인용문 뒤 일반 문단에서 서식을 적용할 때 빈 줄이 늘어났다. 빈 인용을 `<blockquote><p><i></i></p></blockquote>`로 보내면 Android 파서가 빈 p와 인용 경계의 줄바꿈을 중복했다. `<blockquote><br></blockquote>`로 표현해 빈 문단1개를 유지한다. 저장 문서의 블록/문자 좌표는 그대로다.
2. 마지막에 사진이 있는 글의 Select across photos에서 입력하지 않아도 Saving과 문서 버전 증가가 반복됐다. native 이벤트는 마지막 사진 뒤 빈 줄을 생략하고 모델은 그 줄을 보충하므로 재주입이 반복된 것이다. 등록된 마지막 사진 바로 뒤의 줄바꿈1개만 생략된 경우를 구분해 같은 문서를 다시 주입하지 않는다. 사진 앞뒤 문장 합침의 실제 정규화와 Cut 중간 HTML 차단은 유지한다.

최종 타입 검사·변경6개 TS/TSX lint와 nativeEditorHtml/RichBody/EditorImagesNavigation/DraftsNavigation의 iOS·Android 설정8 suites·72 tests가 통과했다(62.531초, 실패/skip0). 새 회귀 사례는 빈 인용1/2개 왕복, 마지막 사진 뒤 행 생략 이벤트의 반복 저장 방지와 실제 문장 변경의 저장을 검증한다. 앞선44/70 tests 실행은 중간 결과이며 합산하지 않는다.

실제 Android에서는 빈 인용을 포함한 혼합 본문에 굵게→Undo→Redo 후 글자/빈 줄/사진 ID·offset 보존과 저장→재개를 확인했다. 마지막 사진 사례는 수정 후 문서 버전601과 Saved가 유지됐고, 전체 선택→Cut에서 본문/사진이 비고 Undo로 원문과 같은 사진 ID/1071×1188 크기·offset139가 복원됐다. 선택 모드 종료→Close→초안 재개 후 version605와 제목/인용문/사진을 확인했다. [실행과 사용자 세션 보존](FE_MOBILE_EXECUTION_01_RESULT.md#quote-layout-native-20261127)을 따른다.

**추가 관찰:** 빈 인용을 포함한 혼합 본문에서 굵게 적용/Redo 뒤 선택이0으로 접히는 현상은 남는다. 본문·서식·빈 줄·사진 보존 확인을 선택 범위의 지속 보존까지 통과한 것으로 확대하지 않는다. 기존31개 사용자 통과를 취소하거나 재검사 요청으로 바꾸지 않고3단계 선택 방식 잔여에 연결한다.

인용선 바깥 배치·원본 서체는 근거가 있는 미해결로 유지한다. 다음은 다크/큰 글자에서 색·줄바꿈·잘림을 대조하고, 읽기 사진 경계와 위 선택 접힘을3단계 잔여로 검토하는 순서다. 같은 기능 검사31개를 다시 요청하지 않는다.

### 편집기 아이콘 크기·저장 표시·하단 정렬 — 2026-11-26

- 하단 도구는 선택 시 색상만 변경하도록 분리했다. 이전에는 공통 녹색 텍스트 스타일의16 크기가 덮어써져 선택한 도구가 작아졌다.
