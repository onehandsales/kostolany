## 발견과 수정

수정 전 실제 Android 라이브러리의 `Your library`와 배너 문구가 원본보다 얇았다. 코드에서는 `fontWeight: '600'`을 지정했지만 설치된 React Native0.86.3의 `ReactFontManager.getTypeface`는 명시한 기본 시스템 fontFamily를 `nearestStyle`로 처리한다. 이 경로는700 미만을 일반 스타일로 분류한다. 원본 폰트 부재와 별도로 확인한 현재 Android의 굵기 처리 차이다.

- [공통 토큰](../FE/src/shared/theme/tokens.ts)에 `fontWeights.semibold`를 추가했다. Android는700, iOS/web은 기존600을 유지한다.
- 공통 `pageTitle`·`sectionTitle`과 [라이브러리](../FE/src/features/bookmarks/LibraryScreen.tsx)의 배너 강조 문구에 적용했다. 서체·크기·행간·터치 영역은 유지한다.
- 수정 후 실제 Android Home 제목과 Library 제목·배너에서 굵기 변화를 확인했다. 원본과 같은 폰트/정확한 weight를 확보했다는 뜻은 아니다.
- 기존 reference PNG, 앱 데이터 계약, native 소스, 의존성·잠금 파일은 수정하지 않았다. 스타일 갱신 후 Home 화면을 확인하고 Library에 다시 진입했다. 이 확인을 사용자 테스트 글의 앱 재시작 영속성 검증으로 해석하지 않는다.

### 후속 사용자 확인과 편집기 아이콘 — 2026-11-26

기사 읽기 화면의 잘림/겹침, Save to 시트의 표시/닫기, 긴 제목·본문과 키보드 가림 확인을 안내한 뒤 사용자가 “다 정상이기는 해”라고 보고했다. 이3항목은 사용자 확인 통과로 기록하며 에이전트의 재실행이나 원본 동일성 판정과 구분한다.

동시에 사용자는 편집기 사진을 제공하며 B 옆 기울임 버튼이 세로선처럼 보이고 다음 버튼의 의미가 불명확하다고 지적했다. 제공 사진과 현재 코드를 확인한 결과, 위쪽 도구 줄은 굵게(B)·기울임(I)·링크(↗)·키보드 닫기(⌄) 순서다. B/I에 같은 일반 텍스트 스타일을 사용하므로 I가 세로선처럼 보인다. 사진의 링크 버튼은 선택 범위가 없는 상태에서 비활성으로 흐리게 표시되는 현재 규칙에 대응한다.

사진 확인 시점에는 **서식 도구의 아이콘 식별성을 미해결**로 분류했다. 굵은 B·기울어진 I·링크를 나타내는 명확한 아이콘이 보정 대상이었다. S183 원본도 직접 열람했으나 해당 캡처에는 아래 문단 서식 도구만 보여 위쪽 B/I/링크 줄의 원본 동일성을 확정하지 않는다. 이후 보정 결과는 아래와 같다.

### 서식 도구 아이콘 후속 보정 — 2026-11-26

- 기울임: 양끝 획이 있고 오른쪽으로 기울어진 I 모양.
- 링크: 서로 연결된 사슬 모양.

### 편집기 아이콘 크기·저장 표시·하단 정렬 — 2026-11-26

사용자가 위쪽 아이콘 크기, Saved의 중앙 이탈, @를 포함한 하단 도구의 왼쪽 쏠림을 지적했다. 화면에 한글 설명을 표시하지 않는 지시는 유지했다.

- 하단 도구는 선택 시 색상만 변경하도록 분리했다. 이전에는 공통 녹색 텍스트 스타일의16 크기가 덮어써져 선택한 도구가 작아졌다.
- 헤더의 왼쪽·중앙·오른쪽에 같은 비율의 폭을 배정해 Saved를 중앙에 둔다. 저장 실패 재시도 문구는 중앙 영역에서 줄바꿈하고 오른쪽 조작도 가용 폭을 넘으면 줄바꿈할 수 있다.
- 하단 가로 도구 줄은 남는 폭을 채워7개 버튼 간격을 고르게 배분한다. 좁은 화면에서 각 버튼의 최소 터치 폭을 줄이지 않고 기존 가로 스크롤을 유지한다. @는 멘션 삽입 버튼이다.

원복 후 타입 검사·관련3파일 lint·diff 검사를 통과했다. 같은 Android 기사에서 Save to를 다시 열어 구분선이 거의 보이지 않는 이전 표시와 미선택 상태를 확인했다. 이번 변경은 스타일 원복이므로 기능 테스트50개를 재실행하지 않았다. 저장 창은 열린 상태로 유지했다.

목록 사이 선만 제거한 후 타입 검사·변경 파일 lint·diff 검사를 통과했다. 열린 Android 저장 창에서 제목/새 목록 아래 선은 남고 Reading list 아래 선은 사라진 것을 확인했다. 메모리 PNG의 해당 행은 기존 회색에서 흰 배경으로 바뀌었으며 위치·선택 상태는 유지됐다. 이번 단순 표시 변경에 기능 테스트50개를 다시 실행하지 않았다.

앞선 박수 표시와 기록8파일은 `30e696e`로 로컬 커밋됐다. 사용자가 `Save to` 창을 열었다고 알려준 뒤 실행 중인 Android와 [S036 원본 PNG](<../medium/flows/Home/Story detail/Saving a story/screens/02_sc_31edfd53d2874259a6ed5ecbc756d10b.png>)·[흐름 분석](<../medium/flows/Home/Story detail/Saving a story/ANALYSIS.md>)을 직접 확인했다. 이번 비교는 저장 창 영역에 한정한다.

| 항목 | 관찰·수정·남은 차이 |
| --- | --- |
| 비교 조건 | 현재 Android1170×2532 / 390×844 논리 단위, 밝은 배경, 키보드 닫힘, 기본 Reading list 한 행. 원본1179×2556의 DPR은 확정하지 않는다. 원본 배경은 brain 기사이고 현재는 Kris Gage 기사이며 스크롤·시스템 영역이 다르다. |

| 구분선 | 원본 PNG의 y1773/1905/2037/2187 구분선에서 RGB198/198/200(`#c6c6c8`)을 확인했다. 기존 `#f2f2f2` 대신 `sheetDivider`를 만들고 Save to의 selection 변형 헤더와 내부 행에만 적용했다. 다른 시트의 기본 구분선은 유지한다. Android의 hairline 렌더링과 픽셀 정렬까지 원본과 동일하다는 판정은 아니다. |

코드 반영 중 화면이 Home으로 돌아가 같은 Kris Gage 기사와 저장 창을 다시 열었다. 모의 로그인 상태와 해당 글의 미저장 상태는 확인했으나 다른 초안·목록 데이터 전체의 보존 검사로 확대하지 않는다. 에뮬레이터·Metro를 재시작하거나 사용자 사진·원본을 변경하지 않았고 캡처는 메모리에서만 열람했다.

검증: 타입 검사, 변경3개 TS/TSX 파일 lint 통과. 기존 `BookmarkNavigation.test.tsx`·`ListManagementNavigation.test.tsx`·`ListEditingNavigation.test.tsx`를 iOS/Android 설정으로 실행해6 suites·50 tests 통과(86.9초, 실패/skip0)를 확인했다. 실제 iOS 실행을 의미하지 않는다. 새 스타일 전용 테스트는 추가하지 않았다. 변경 문서의 로컬 링크1559개를 검사해 신규 누락0·새 명시 anchor2개 존재를 확인했다. 비교 기준 문서의 과거 PARITY_01 PNG 링크10개는 HEAD에서도 목적지 파일이 없는 기존 상태이며 이번에 증거 파일을 새로 만들거나 연결을 완료 처리하지 않았다.

현재2단계 진행 중이며 S036은 부분 보정이다. 동일 배경/상태의 전체 비교, 원본 서체·세부 수직 간격·아이콘 형태, Dark·큰 글자·실제 iOS 검증은 남는다. [비교 기준 S036](MEDIUM_PARITY/COMPARISON_BASELINE.md#s036)의 recipe-only 상태를 전체 완료로 올리지 않는다. 다음은 S042/S183 편집기의 원본 대비 배치·타이포 대조이며 전체 아이콘/버튼 체계 통일은 계속 보류한다. 이번 변경은 미커밋이다.

후속 사용자 요청으로 최종 제목 강조·목록 사이 선 제거 코드2파일과 관련 문서4파일을 로컬 커밋 대상으로 확정했다. 위 미커밋 문구는 요청 전 기록이다. 마지막 타입/lint·Android 화면 확인 이후 제품 코드 변경은 없으며 커밋 전 diff·문서 링크를 검토한다. 다음 사용자 확인은 Done→기사 뒤로→홈 연필→빈 편집기에서 키보드와 상단/하단 도구의 배치 확인이다. 이후 S042·S183 원본 대조로 진행하며 사용자 확인을 원본 동일성 완료로 대신하지 않는다.
