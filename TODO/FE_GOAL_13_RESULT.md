- `createLikeStore`, `createBookmarkStore`, `createUserListStore`, `createLibraryStore`: 빠른 연속 목표, 오래된 성공/실패·조회, 중복 저장, 다중 소속, 삭제와 수정/추가 경합, 삭제 후 부활 방지.
- `ProfileNavigation`, 프로필 store/화면: A 조회·저장 중 B 전환 후 늦은 응답, 초안 격리, 재로그인 이름 유지, ID·revision·개인 데이터 보존.
- `SettingsNavigation`, 설정 store/화면, `ExplanationPreference`: 조회 중 수동 선택, 기본값/임시 선택 분리, 저장 최신 제출, 이전 실패/조회 차단, A/B/A와 같은 A 세션 정리.
- `ArticleRouteScreen`, `AuthBoundaryNavigation`: 삭제된 목록과 다른 사용자 소유의 같은 목록 ID로 잘못 복귀하지 않음.

이 항목 전체를 브라우저 지연 주입으로 실행한 것은 아니다. 결정적인 지연·순서·같은 A 재로그인 경계는 제어 가능한 Promise를 주입한 Jest로 검증했고, 대표 정상·실패·취소·사용자 전환은 브라우저로 검증했다. navigation 통합 테스트에서 React Navigation 자체를 mock하지 않았다. RN 네이티브 기반은 jest-expo/Safe Area 대체 환경이다.

## 8081 최종 확인 순서

1. `http://localhost:8081`을 전체 새로고침한다. 홈에서 최신/인기/추천과 **기사 더 보기**를 확인한다. 탐색에서 **금리**를 검색해 기사를 열고 설명 수준을 바꾼 뒤 돌아온다.
2. 좋아요나 저장을 누르면 로그인 화면이 열린다. **모의 동작 선택 열기**에서 사용자 취소/실패를 확인한다. 실패 후 다시 시도하면 성공한다. 성공 직후 좋아요·저장은 자동 실행되지 않으므로 다시 직접 누른다.
3. A로 좋아요·저장한 기사를 라이브러리의 **읽기 목록**에서 다시 연다. 라이브러리에서 목록 두 개를 만들고 기사 옆 **⋯**에서 두 목록을 선택·적용한다.
4. 사용자 목록→기사→뒤로 복귀 후 **목록 관리**에서 이름을 바꾸고, **이 목록에서 제거** 및 목록 삭제 취소/확인을 해 본다. 남은 목록·좋아요·기사 원문을 확인한다.
5. 프로필→편집에서 취소와 이름·소개 저장을 확인한다. 설정에서 **중학생**을 기본값으로 저장한 뒤 홈/검색/읽기 목록에서 기사를 새로 열어 확인한다. 기사 안에서 고등학생으로 바꿔도 다음 새 진입은 중학생이다.
6. 설정의 로그아웃에서 취소·실패·다시 시도를 확인한다. B로 로그인해 초기 이름·성인 기본값·빈 개인 목록을 확인하고, 다시 A로 로그인해 A 데이터를 확인한다.
7. 전체 새로고침하면 guest로 돌아간다. A로 로그인해 초기 이름·성인 기본값·빈 개인 데이터인지 확인한다.

인증 외 조회/저장 실패를 수동 재현하려면 `FE/README.md` 각 기능의 `*Preview.ts` 시나리오를 바꾸고 전체 새로고침한다. 확인 후 반드시 `normal`로 되돌린다. 자동 재현은 evidence의 실패 스크립트를 사용하며 기존 `/tmp/kostolany-goal8-browser`의 Playwright와 설치된 Chrome을 사용한다. 앱에 디버그 메뉴나 외부 계정 설정을 추가하지 않았다.

후속 개발은 자동으로 시작하지 않는다. 남은 필수 네이티브 검증을 실제 기기/시뮬레이터 환경에서 수행하기 전까지 구현 완료와 검증 대기를 구분한다.
