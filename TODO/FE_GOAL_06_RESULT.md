# Goal 6 — 기사 검색과 검색 결과

검토일: 2026-11-18 KST. **구현·자동 검증·PC 브라우저 흐름·모바일 폭 원본 비교 완료. 실제 iOS·Android 실행과 네이티브 화면 비교는 미검증.**

## 구현과 확인 경로

기존 미리보기 [localhost:8081](http://localhost:8081)에서 **탐색 → 기사 검색 → `금리` 입력 → 결과 선택 → 상단 뒤로 가기**로 확인한다. `탐색으로 돌아가기`는 기사 상세 진입 전의 검색어와 결과를 유지한다. 라이브러리·프로필은 기존 준비 화면이다.

- 탐색 첫 화면: 제목, 회색 검색 진입창, 금융 주제 칩, 순번이 있는 고정 예시 기사 목록.
- 검색: 입력창·뒤로 가기·지우기, 빈 입력의 주제 바로가기, 기사 분류 밑줄과 결과 수, 검색 전용 카드.
- 상태: 로딩, 결과 없음, 조회 실패와 같은 검색어 재시도. 빈 입력에서는 조회하지 않는다.
- 응답 관리: 250ms debounce, 입력 변경 시 이전 결과 즉시 숨김, 오래된 성공·실패 무시. `A → B → A`에서도 최초 A 응답을 재사용하지 않는다.
- 연결: 선택 ID로 기존 상세를 열고 진입 탭에 맞는 뒤로 가기 label을 표시한다. 상세의 사실 요약·4단계 설명은 기존 구현을 유지한다.
- 복귀: Main 탭을 유지하므로 검색어·조회 결과가 남는다. Chrome에서 스크롤 위치도 보존됨을 확인했다. 앱 재실행·새로고침 후 영속 복원은 구현하지 않았다.

## 예시 검색 규칙 — 화면용 기본안

이 규칙은 실제 서버 검색 계약·검색 엔진·제품 정책의 확정안이 아니다.

| 항목 | 이번 기본안 |
| --- | --- |
| 대상 | 홈에 있는 고유 예시 기사 10개의 제목·요약·출처. 본문·AI 해석은 제외 |
| 정규화 | Unicode NFC, 앞뒤 공백 제거, 연속 공백을 한 칸으로, 영문 소문자 변환 |
| 일치 | 공백으로 나눈 모든 단어가 제목/요약/출처를 합친 문자열에 포함되는 리터럴 부분 일치(AND). 정규식·형태소·오타 보정 없음 |
| 순서 | `feedFixtures.latest` 4개 → `popular` 3개 → `recommended` 3개 순서를 보존. 날짜·관련도·조회수로 재정렬하지 않음 |
| 수량 | 일치한 결과 전부 표시. 최대 10개라 검색 페이지 나누기 없음 |
| 입력 | 최대 100자, 마지막 입력 변경 후 250ms에 요청. 기본 mock 응답 지연 200ms |
| 빈 값 | 검색 요청 없이 주제 안내. 공백만 있는 입력도 동일 |
| 상태 저장 | 현재 탭 인스턴스 메모리. 계정·기기 저장소·서버 저장 없음 |
| 주제/순번 | 금융 키워드는 같은 검색의 바로가기. 첫 화면의 순번은 fixture 순서이며 인기 집계·토픽 계층·팔로우를 뜻하지 않음 |

확인 예: `금리` 2건, `금리 계약` 1건, `환율` 1건(이미지 없음), `심리` 1건(요약 일치), `Kostolany` 10건(출처 일치), `없는기사` 0건.

[searchPreview.ts](../FE/src/features/search/data/searchPreview.ts)는 `normal / initial-error / slow / out-of-order`를 제공한다. 각 오류는 정규화한 검색어별 첫 요청에서 한 번 발생한다. 전체 Reload로 실패 이력을 초기화하며 검증 후 `normal`로 복원했다. [재현 방법](../FE/README.md#기사-검색과-탐색)을 참고한다.

Jest에 추가한 16개 논리 테스트는 debounce, 정규화·AND·리터럴 검색·순서, 빈 입력/결과 없음, 결과 ID 선택, 실패·중복 재시도 방지, 늦은 성공/실패, A→B→A, 지우기, 이전 목록 즉시 제거, 잘못된 응답 query·동기 예외, StrictMode·공급부 교체, 상세 복귀와 탭 왕복을 다룬다. 상세 복귀는 상단 버튼과 모의 native back event를 각각 확인했다. 실제 navigation과 화면을 사용하며 통째로 mock하지 않았다. 기존 홈·상세·설명 수준 테스트도 통과했다.

브라우저 검증은 격리된 headless Chrome에서 DOM을 읽고 실제 입력·클릭을 수행한 결과다. 스마트폰 터치·OS 키보드·한글 IME 조합·Dynamic Type·VoiceOver/TalkBack·iOS 스와이프는 확인하지 않았다. 큰 글꼴에서는 카드 제목과 이미지를 세로로 배치하도록 구현했지만 실제 기기의 글자 확대와 Safe Area 결과는 여전히 검증 대기다. 상단 앱 뒤로 가기와 브라우저 툴바의 이전 페이지 이동을 동일한 기능으로 기록하지 않는다.

## 코드 검토와 보존

- 검색 화면과 fixture 공급부를 분리했다. 화면은 결과 상태와 선택 ID를 다루며 외부 연결·키·ENV가 없다.
- 정규화한 query별 컴포넌트 수명, effect 정리, source 일치 검사로 이전 응답을 차단한다. 빈 query는 요청하지 않고 같은 정규화 값으로 공백/대소문자만 바꾸면 재조회하지 않는다.
- 재시도는 오류 상태에서만 열고 진행 중 중복 실행을 막는다. 응답 query 불일치와 동기 source 예외도 오류 UI로 전환한다.
- 검색 전용 카드를 사용해 원본의 전체 폭 요약을 구현했다. 기존 홈 카드를 재배치하지 않았다.
- 이미지 검토에서 발견한 입력창 배경의 글자 가림을 z-index로 수정하고 브라우저 화면을 다시 확인했다. 회색 면 36px와 조작 높이 48px를 분리했다. 큰 글꼴의 세로 배치에서 제목이 접히지 않도록 flex를 분리했다.
- 시작 시 기존 미커밋 파일 35개의 SHA-256을 보관했다. 이 중 navigation 연결·상세 back label·진행 문서의 6개 파일만 필요한 부분을 갱신했고 나머지 29개는 동일 바이트로 보존했다. `App.test.tsx`의 탐색 placeholder 기대값도 실제 검색 화면 기준으로 갱신했다.
- 기존 package/lockfile·웹 설정·4단계 설명 코드와 fixture는 보존했다. `medium/flows`, BE 변경 없음. 기존 localhost 미리보기 서버를 유지했다.
- 커밋·push·배포·Goal 7 작업은 수행하지 않았다. 기존 audit 경고는 이번 범위에서 재검사하거나 수정하지 않았다.
