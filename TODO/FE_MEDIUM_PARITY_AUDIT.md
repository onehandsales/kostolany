## 동일 재현의 완료 기준

원본의 화면 요소·문구·데이터·배치·글꼴·자산·색·선택 상태, 보이는 조작의 결과와 복귀, 화면 사이 공유 상태를 각각 확인해야 한다. 동작이 같아도 다른 선택 화면을 쓰면 UX 차이이고, 화면이 비슷해도 다른 기능으로 연결되면 연결 결함이다. 같은 화면이라도 빈값/선택/로딩/오류/스크롤/키보드/다크 상태는 별도다.

과거 Goal53의200개 판정은198개 부분 대조와2개 비동등(S043 시작 화면,S113 OS picker)이다. 이번에200개 현재 FE 화면을 다시 촬영한 것은 아니다. 기존의 폰트/자산/배치 차이는 원본 동일성 기준에서 여전히 잔여다. 허용 오차나 미확인을 임의로 통과시키지 않는다.

원본 미수록 동작은 동일 여부를 확정할 수 없다. 예컨대 초안 삭제는 조사 대상으로 있었지만 캡처에 삭제 UI가 없으므로 이번 판정은 자료 확인 대기다. 반면 S008의 보이는 도구는 원본 근거가 있으므로 UI/연결 작업으로 분리했다. 모호한 경우를 전부 기능 누락 또는 전부 제외로 처리하지 않았다.

실제 native 기기 검증은 사용자 후속 진행으로 남긴다. native 선택 UX 같은 **구현 차이**와 OS picker/공유 등 **실제 실행 미검증**을 나누었다. 실제 OAuth/메일/결제/Push/TTS/AirPlay/영속 오프라인 등은 기존 fixture·mock 범위 밖이며 서비스 효력까지 동일하다는 주장은 하지 않는다.
