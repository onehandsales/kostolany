## 상태·소유권·출력 계약

- 목록 원본은 기존 UserListSource 하나다. 사용자 ID와 목록 ID의 쌍으로 소유권을 검사한다. 공개 목록 전체 Save 관계와 개별 기사 저장을 변경하지 않는다. 방문자의 Saved lists 다운로드 확장은 이번 근거에 포함하지 않는다.
- DownloadSource는 `getLists/getVersion/isOnline/subscribe/load` 계약을 제공한다. load 입력과 결과의 사용자·목록·기사·job ID를 모두 대조한다. source는 요청 전후에 소유자와 현재 기사 소속을 확인한다.
- snapshot은 목록 제목/설명/메모/순서/공개 상태를 복사한다. 기사 사본은 ID·콘텐츠 버전·본문·수신 순서를 갖는다. source의 콘텐츠 버전은 삭제 후 재등록해도 증가한다. 목록 화면은 현재 원본을 표시하고 사본은 수신 당시 버전임을 구분한다.
- store는 사용자별로 하나이며 인증 revision 수명에서 활성화된다. 실제 AuthStore의 현재 사용자/revision까지 확인해 React cleanup 이전의 늦은 응답도 차단한다. 프로필 이름/기본 설정 변경으로 revision을 새로 만들지 않는다.
- 같은 목록의 중복 시작은 같은 Promise를 반환한다. 새 job/취소/제거/source 알림은 이전 controller를 폐기한다. 부분 실패 재시도는 동일 snapshot·동일 버전의 성공 항목을 재사용하고 빠진 항목만 받는다. 읽기 요청의 응답 유실은 외부 쓰기/집계를 중복시키지 않는다.
- 원본 목록 삭제는 job과 사본을 제거한다. 기사 제거는 해당 관계의 사본만 제거한다. 다른 목록의 같은 기사 사본은 유지하며 가장 최근 수신한 유효 사본을 읽는다. 원본 기사가 삭제되면 과거 사본을 이용할 수 없다.
- 취소는 받은 항목을 남기고 Remove download는 사본을 전부 지운다. 다시 시작은 현재 원본 기준이다. 오래된 성공·실패는 취소/새 job/계정 전환 뒤 현재 결과를 덮지 않는다.
- `setOnline`은 검증용 mock 연결 상태이며 실제 OS 네트워크 감지가 아니다. 본문과 번들 자산 참조만 메모리에 보관한다. 브라우저 offline 확인도 이미 로드한 앱/이미지 환경이다. 새 기기·콜드 시작·이미지 파일 영구 보관을 입증하지 않는다.
- 사본의 내용 범위는 기존 로컬 기사 fixture와 같다. 부분 본문이나 미수록 본문 안내도 그대로 유지한다. 완료 표시는 이 payload의 메모리 수신 완료이며 Medium 원본 전체 본문을 확보하거나 다운로드했다는 뜻이 아니다.
