## 입력 기본안

| 항목 | 처리 |
| --- | --- |
| 이름 | 필수, 제출 때 NFC 정규화·앞뒤 공백 제거·연속 공백/줄바꿈/탭을 한 공백으로 합침, 최대 50 코드 포인트 |

## 저장·조회·취소·경합

- 조회 전/중, 조회 실패·수동 재시도를 표시한다. 확정 값이 없는 동안 편집 진입을 제공하지 않는다. 재조회 실패는 기존 확정 값을 지우지 않는다. 자동 무한 재시도는 없다.
- 프로필 이름과 소개를 하나의 목표로 제출한다. 공급부 응답의 userId·입력 형식·정규화·제출 내용 일치를 검증한다. 성공 전까지 화면의 확정 이름은 바꾸지 않는다.
- 한 사용자에 한 쓰기만 진행한다. 처리 중 다른 저장을 제출하면 **대기 중 마지막 목표**만 남긴다. 같은 목표 중복 제출은 같은 Promise를 공유한다. 중간 목표는 superseded로 끝난다.
- 첫 저장 뒤 원래 값으로 다시 저장하는 의도도 처리한다. 현재 확정 값과 같다는 이유로 진행 중 변경의 취소 목표를 생략하지 않는다.
- 저장 중에도 입력할 수 있다. 제출한 내용과 같으면 중복 저장 버튼을 잠그고, 추가로 바꾸면 `추가 저장`을 제공한다. 이전 성공은 새 입력을 지우거나 편집창을 닫지 않는다. 최신 제출이 성공하고 그 뒤 추가 입력이 없을 때만 닫는다.
- 최신 저장 실패는 확정 값을 유지하고 **열려 있는 입력을 보존**한다. `다시 시도`는 현재 초안을 다시 검증해 제출하므로 실패 뒤 수정할 수 있다. 오래된 실패는 더 최신 제출의 오류가 되지 않는다.
- 제출은 조회 세대를 무효화한다. 늦은 조회 성공/실패가 저장 결과를 덮지 않는다. 편집 중 새 조회가 와도 초안을 다시 초기화하지 않는다.
- 취소·닫기·Modal 뒤로·탭 이탈은 미제출 초안을 버린다. **닫기는 이미 제출한 저장 요청의 취소가 아니다.** 안내 문구를 표시하고 제출은 원래 사용자의 저장소에서 계속된다.
- 닫힌 화면의 callback은 재오픈·닫기·오류 표시를 하지 않는다. 저장 중 닫고 새 편집을 열면 새 초안은 이전 응답과 독립적이다. 닫은 뒤 저장 실패는 프로필에서 알리며, 초안 폐기 정책에 따라 다시 편집해서 입력한다.
- 로그아웃·계정 전환은 개인 화면 키를 바꿔 모달·초안·로컬 오류를 정리한다. 늦은 A 응답은 A 저장소만 갱신하고 B 프로필·초안·인증·revision을 변경하지 않는다. 새 사용자에게 이전 화면을 잠시 제공하는 effect 기반 교체가 아니다.

직렬화로 같은 사용자의 저장 응답 역전 자체를 방지한다. mock 실패는 반영 전 실패다. 서버 반영 후 응답 유실, 다중 기기 변경, 서버 버전·멱등성·권한 검증은 실제 연동의 후속 계약이다.

## 메모리 수명

Goal 10 정책을 유지했다. 기본 ProfileSource와 사용자별 캐시는 Provider/앱 실행 수명의 메모리다. 프로필·인증·개인 데이터에 기기 저장소·쿠키·서버 저장을 추가하지 않았다.

- 화면 재진입: 마지막 확정 프로필 재사용. 미제출 초안은 복구하지 않음. 제출한 요청은 계속 진행.
- 로그아웃 후 같은 A 및 A→B→A: A의 확정 프로필과 진행 중 요청 결과 보존. B와 합치거나 이전하지 않음. 인증 이름 fixture는 프로필 초기화에 쓰지 않음.
- 전체 새로고침·앱 프로세스 재실행: 비로그인, 기본 프로필 fixture로 초기화. Fast Refresh에서 상태 보존을 보장하지 않음.
- 공급부 교체: 별도 캐시 범위로 교체하고 이전 응답 격리. 주입한 테스트 공급부의 메모리 수명은 해당 공급부 생성자가 소유.
- 실제 앱은 두 mock 사용자 범위다. 임의 계정의 영속 보관·삭제·대규모 캐시 관리가 구현됐다는 뜻이 아니다.

- iOS: Command Line Tools만 있고 Xcode.app·xcodebuild·simctl이 없어 시뮬레이터/기기 실행·네이티브 빌드 미실행.
- Android: 확인한 경로에 Android SDK가 없고 adb·emulator가 없어 기기/에뮬레이터 실행·네이티브 빌드 미실행. Java 23 설치만으로 Android 빌드 성공을 주장하지 않는다.
- 실제 Safe Area·가상 키보드 가림·OS 한글 IME 조합/자동완성·OS 글자 확대·VoiceOver/TalkBack·iOS 제스처·Android 시스템 뒤로 가기는 미검증. SafeAreaView·KeyboardAvoidingView·ScrollView·Modal 이벤트 코드, 웹과 Jest 검증은 이 검증을 대신하지 않는다.

## 8081 확인 방법

1. `http://localhost:8081` → **프로필 → 로그인 → 예시 독자 A → Google로 로그인 (모의)**.
2. **프로필 편집**에서 기존 이름·빈 소개를 확인한다. 이름·소개를 바꾸고 **저장**, 다시 편집해 확정 값을 확인한다.
3. 입력한 뒤 **취소·닫기·Escape**로 닫고 다시 열면 미제출 값이 사라진다. 이름을 비우거나 50자 초과, 소개 160자 초과로 저장해 오류를 확인한다.
4. **로그아웃** 확인 문구의 이름을 확인하고 취소한다. 실제 로그아웃 후 B로 로그인하면 B 이름·소개를, 다시 A로 로그인하면 A의 수정 값을 확인할 수 있다. 계정 선택 A/B 표시는 고정이다.
5. 실패·느린 처리 재현은 `FE/src/features/profile/data/profilePreview.ts`의 `profilePreviewScenario`를 바꾸고 브라우저를 **전체 새로고침**한다. `read-error`: 사용자별 첫 조회 실패→조회 다시 시도. `save-error`: 사용자별 첫 변경 저장 실패→입력 보존→수정→다시 시도. `slow`: 조회/각 저장 약 4초, 저장 중 추가 수정·추가 저장·닫기·재진입 확인. 정상은 `normal`, 약 350ms다.
6. 확인 후 `normal`로 복원한다. 전달 상태는 `normal`이다. 전체 새로고침은 인증·프로필·개인 데이터 메모리를 초기화한다.

Goal 11 산출물만 전달한다. 이전 Goal의 미검증을 완료로 바꾸지 않았으며 Goal 12는 시작하지 않았다.

## 후속 커밋 요청

구현 보고 후 별도 사용자 요청에 따라 Goal 11 코드·테스트·문서·화면 증거를 로컬 커밋으로 기록한다. Node 24의 타입·lint·512건 테스트 통과와 양 플랫폼 JS 번들·브라우저 검증 기록을 확인했다. 기능 코드를 변경하지 않아 전체 검사를 반복하지 않는다. `platforms.json`의 `committed: false`는 검증 당시 상태로 유지한다. 원격 push·배포는 하지 않으며, Goal 12는 요청문만 안내하고 구현을 시작하지 않는다.
