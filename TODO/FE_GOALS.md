## 목표와 현재 범위

최종 방향은 Medium 모바일의 화면과 흐름을 충실하게 재현하는 것이다. 먼저 1차 MVP에 해당하는 React Native 화면을 구현한다. iOS·Android가 대상이며, 금융 뉴스·AI 해석·4단계 설명이라는 기존 서비스 방향을 유지한다.

이번 계획은 **프론트엔드 화면 구현 단계**다. 실제 서비스 전체의 1차 MVP 완료와 구분한다.

- 대상: 홈, 탐색, 기사 상세, 설명 수준 선택, 반응, 라이브러리, 모의 로그인, 프로필, 설정.
- 하단 메뉴: **홈 · 탐색 · 라이브러리 · 프로필** 4개. 설정은 프로필에서 진입하는 구성으로 시작한다.
- 데이터와 인증: fixture·mock으로 제공한다. 화면 코드와 데이터 접근을 분리해 이후 실제 API로 교체할 수 있게 한다.
- 제외: 백엔드 구현, 실제 Supabase DB·Auth·Storage 연결, 실제 Google 인증, RSS·AI 공급자 호출, 배포.
- 글쓰기·댓글·팔로우·결제 등 Medium의 나머지 기능은 후속 범위다. 이 계획의 완료를 Medium 전체 재현 완료라고 표현하지 않는다.
- 조회수·정렬 결과는 임시 데이터로 표현한다. 실제 집계·추천 알고리즘이나 사업 정책을 확정한 것으로 기록하지 않는다.

## Goal 운영 방식

**큰 Goal 하나에 전체 작업을 넣지 않는다. 아래 13개를 각각 별도의 Goal로 실행한다.**

1. 사용자가 요청한 Goal 하나만 시작한다. 아래 번호는 기본 진행 순서이며, 앞선 구현 상태를 먼저 확인한다.
2. 해당 Goal의 범위와 완료 조건을 확인하고, 필요한 Medium 화면만 조사한다.
3. 구현과 테스트 코드 작성을 함께 진행한다.
4. 변경 코드와 테스트를 검토하고, 관련 검증에서 발견한 문제를 수정한다.
5. 원본 화면과 구현 결과, 실행한 검증, 미검증 항목을 기록한다.
6. 완료 조건을 충족하면 해당 Goal을 완료하고 결과를 보고한 뒤 종료한다.
7. **다음 Goal은 자동으로 생성하거나 시작하지 않는다. 사용자의 별도 요청을 기다린다.**

진행 중 일상적인 구현 선택마다 승인을 요청하지 않는다. 중요한 범위 변경이나 계정 인증 등 사용자 입력이 필요한 경우에는 이유를 명확히 설명한다. 요청된 Goal의 구현·검토·검증은 끝까지 수행하되, 다른 Goal의 기능을 함께 구현하는 방식으로 범위를 넓히지 않는다.

커밋과 배포는 별도 요청이 있을 때만 수행한다. 이 문서 작성 자체는 Goal 실행 요청이 아니다.

## 공통 완료 조건

- 해당 Goal의 구현과 중요한 사용자 행동·실패 사례를 검증하는 **테스트 코드 작성이 필수**다.
- React Native Testing Library 등을 사용한다. 실제 도구·버전·실행 명령은 Goal 1에서 호환성을 확인하고 고정한다.
- 타입 검사·lint·관련 테스트를 통과하고, 코드 검토에서 발견한 문제를 수정한다. 변경이나 새로운 우려가 없으면 같은 검증을 불필요하게 반복하지 않는다.
- 단순 스냅샷·렌더링 확인만으로 상호작용 기능의 검증을 대신하지 않는다. 구현 줄 수를 그대로 반복하는 테스트나 형식적인 커버리지 목표를 만들지 않는다.
- 시각적 변경은 실제 모바일 실행 화면과 원본을 비교한다. 타입 검사·컴포넌트 테스트 통과만으로 시각적 일치를 주장하지 않는다.
- Safe Area, 긴 한국어, 글자 확대, 접근성 label, 뒤로 가기와 관련된 영향을 확인한다.
- iOS와 Android의 실행·빌드 결과를 각각 기록한다. 웹 미리보기나 한 플랫폼 성공을 두 플랫폼 검증으로 기록하지 않는다.
- 필요한 실행 환경이 없어 확인하지 못한 항목은 미검증으로 남긴다. 해당 Goal의 필수 완료 조건을 충족하지 못했다면 구현 상태와 검증 대기를 구분해 보고한다.
- mock 테스트와 실제 외부 연동을 구분한다. 실제 인증·DB 저장·RSS 처리를 완료했다고 표현하지 않는다.
- 변경 파일, 검토 내용, 검증 명령·결과, 남은 문제를 기록한다.

## Medium 화면 확인 기준

- 기존 조사에서는 Medium iOS 선택 화면 10장을 확인했다. 전체 200장을 확인한 상태가 아니다.
- 각 Goal에서 참고하는 앱 버전, 플랫폼, 화면 ID, 원본 링크, 조회일을 기록한다.
- 원본 화면과 구현 화면을 연결해 누락을 관리한다. 이번 Goal에서 제외되는 원본 기능은 후속 범위로 표시한다.
- 확인하지 못한 화면·동작은 미확인으로 남긴다. 다른 자료나 자체 제안을 원본 관찰 결과처럼 쓰지 않는다.
- 배치·간격·글자 위계·탭·모달·상태 표현을 임의로 단순화하지 않는다. 금융 콘텐츠와 4단계 설명처럼 우리 앱이 추가하는 요소는 구분한다.
- Medium의 로고·글·사진을 서비스 자산으로 복사하지 않는다. 구조를 참고하고 자체 명칭과 콘텐츠를 사용한다.
- 전체 화면 조사나 거대한 디자인 시스템 완성을 Goal 1의 선행 조건으로 두지 않는다.

## Goal별 범위·테스트·완료 조건

각 Goal의 완료 조건에는 위 공통 완료 조건이 함께 적용된다. 데이터 동작은 모두 fixture·mock 기준이다.

### Goal 1 — 프로젝트 초기화와 테스트 환경

- 구현: React Native 초기화, TypeScript strict, lint·테스트 환경, 최소 시작 화면, 설치·실행 안내. Expo·navigation 등은 AGENT에 따라 호환성을 확인해 선택하고 lockfile로 고정한다.
- 테스트: 앱 진입점에서 시작 화면이 정상적으로 나타나는 기본 테스트를 작성하고 실행한다.
- 완료: 타입 검사·lint·테스트가 통과하고, 가능한 모바일 환경에서 시작 화면을 확인한다. 플랫폼별 실행 여부와 필요한 환경을 기록한다.
- 경계: 홈·탐색 등 기능 화면과 4개 탭은 다음 Goal의 범위다. 백엔드·Supabase 설정을 변경하지 않는다.

### Goal 2 — 공통 스타일과 하단 탭 이동

- 구현: 이번 화면들에 필요한 최소 색상·타이포·간격·공통 컴포넌트, 홈·탐색·라이브러리·프로필 탭. 각 탭 내부는 아직 기능이 없는 임시 화면으로 구분한다.
- 테스트: 탭을 누르면 올바른 화면과 선택 상태가 표시되는지, 접근성 이름으로 조작할 수 있는지 검증한다.
- 완료: 4개 탭 이동이 동작하고 원본 하단 탐색과 실행 화면을 비교했다. 이후 기능 전체를 이 Goal에 포함하지 않는다.

### Goal 3 — 홈 피드와 기사 카드

- 구현: Medium 기준의 피드 배치와 카드, 최신·인기·추천 전환의 UI, 목록 로딩·빈 결과·오류·재시도·추가 불러오기. 실제 정렬 정책 대신 구분 가능한 fixture를 사용한다.
- 테스트: 탭과 표시 데이터의 일치, 카드 선택, 재시도, 추가 요청 중복과 끝 페이지를 검증한다.
- 완료: 피드의 정상·실패 상태를 재현할 수 있다. 상세 화면 구현 전에는 카드가 전달하는 기사 ID까지만 검증한다.

### Goal 4 — 기사 상세

- 구현: 홈에서 선택한 기사의 제목·출처·시각·이미지·본문과 뒤로 가기. 사실 설명과 AI 해석을 구분하는 fixture를 사용한다.
- 테스트: 선택한 기사와 상세 데이터의 일치, 이미지 없는 기사, 상세 조회 실패·재시도, 홈 복귀를 검증한다.
- 완료: 홈 → 상세 → 홈이 동작하고 긴 한글 본문의 읽기 화면을 원본과 비교했다. 설명 수준 전환·반응 동작은 후속 Goal이다.

### Goal 5 — 4단계 설명 전환

- 구현: 초등학생·중학생·고등학생·성인 선택과 해당 설명·예시 표시. 실제 나이 입력은 추가하지 않는다.
- 테스트: 4개 선택 각각의 본문·예시, 빠른 변경 후 마지막 선택 유지, 비동기 mock을 사용하는 경우 지연·실패 응답을 검증한다.
- 완료: 선택 표시와 본문·예시가 일치한다. 초기값은 화면용 기본안으로 기록하고 서버 저장 정책을 확정하지 않는다.

### Goal 6 — 기사 검색

- 구현: 검색 입력, 임시 기사 데이터의 검색 결과, 결과 없음, 로딩·오류·재시도, 결과에서 상세 진입.
- 테스트: 검색어 변경과 결과 일치, 빈 검색어·검색 결과 없음, 오래된 응답 처리와 결과 선택을 검증한다.
- 완료: 탐색 → 검색 결과 → 상세 흐름을 실행할 수 있다. 서버 검색 엔진이나 실제 API는 구현하지 않는다.

### Goal 7 — 좋아요 등록·해제

- 구현: 좋아요 상태와 반응 수의 모의 갱신. 원본의 반응 UI를 참고하되 다중 박수 집계 정책을 임의로 확정하지 않는다.
- 테스트: 등록·해제, 연속 조작, 실패 시 복구, 같은 기사의 목록·상세 상태 일치를 검증한다.
- 완료: mock 결과에 따라 상태가 일관되게 갱신된다. 인증 없이 검증할 수 있도록 모의 사용자 상태를 사용하고 로그인 UI는 Goal 10에서 구현한다.

### Goal 8 — 북마크와 저장 목록

- 구현: 기사 저장·해제, 기본 읽기 목록, 빈 목록, 저장한 기사에서 상세 진입. 사용자별 상태는 mock에서 분리한다.
- 테스트: 중복 저장 방지, 해제 후 목록 반영, 목록·상세 상태 일치, 모의 저장 실패 복구를 검증한다.
- 완료: 기사 → 저장 → 라이브러리 → 같은 기사 흐름이 동작한다. 저장 위치와 앱 재실행 시 유지 여부를 명시하고 실제 DB 영속 저장과 구분한다.

### Goal 9 — 라이브러리 목록 관리

- 구현: 사용자 목록 생성·이름 수정·삭제와 목록별 기사 추가·제거. 기존 기본 읽기 목록과 연결한다.
- 테스트: 입력 검증, 편집 취소, 목록 간 데이터 구분, 삭제 후 화면 상태, 작업 실패 시 복구를 검증한다.
- 완료: 목록 관리에서 상세 읽기까지 동작한다. 목록 삭제가 원본 기사를 삭제하지 않으며, 기본 목록 삭제 규칙 등 필요한 동작을 구현 시 명시한다. 공개 목록·공유·댓글은 후속 범위다.

### Goal 10 — 모의 로그인·취소·로그아웃

- 구현: Medium을 참고한 로그인 진입 화면, Google 로그인 버튼의 모의 성공·취소·실패, 원래 화면 복귀, 로그아웃.
- 테스트: 각 인증 결과의 화면 이동, 취소 시 상태 유지, 로그아웃·모의 사용자 전환 시 개인 데이터 분리를 검증한다.
- 완료: 외부 계정 없이 fixture로 인증 UI 흐름을 검증한다. 실제 토큰이나 Supabase 세션을 만들지 않는다. 로그인 요구 시점은 실제 제품 정책과 구분해 기록한다.

### Goal 11 — 프로필 조회·수정

- 구현: 모의 사용자 정보 표시와 이름·소개 편집, 저장·취소·실패 처리. 글쓰기와 작성자 통계는 포함하지 않는다.
- 테스트: 기존 값 표시, 편집 저장·취소, 입력 오류, 실패 후 입력 보존, 사용자 전환을 검증한다.
- 완료: 조회와 편집 화면의 모의 데이터가 일치하며, 편집 취소가 기존 값을 변경하지 않는다.

### Goal 12 — 설정

- 구현: 프로필에서 설정 진입, 기본 설명 수준 변경, 기존 로그아웃 흐름 연결. 해당 기능에 필요한 최소 설정만 구현한다.
- 테스트: 설정한 수준이 다음 기사 진입에 반영되는지, 변경 취소·저장 실패 시 기존 상태가 보존되는지 검증한다.
- 완료: 설정·기사의 설명 수준 상태가 일관된다. 기기 내 보관 여부와 범위를 기록한다. 푸시·결제 설정을 추가하지 않는다.

### Goal 13 — 전체 흐름 검증

- 구현: 앞선 Goal에서 만든 화면의 연결 누락과 기존 범위 내 결함을 수정한다. 새 제품 기능을 추가하는 Goal이 아니다.
- 테스트: 모의 로그인 → 기사 찾기 → 상세 → 설명 수준 전환 → 반응 → 목록 저장 → 다시 찾기 → 로그아웃을 연결해 검증한다. 기존 테스트를 활용하고 흐름 연결의 빈틈을 검증할 테스트를 보완한다.
- 완료: 1차 FE 대상 화면 목록과 구현을 대조하고, 원본·자체 확장·후속 범위·미확인 항목을 구분했다. 타입 검사·lint·관련 테스트 및 플랫폼별 실행 결과를 기록한다.
- 경계: 이 Goal의 결과는 프론트엔드 검증이다. 실제 RSS·AI·인증·DB 연결이나 스토어 출시 완료로 보고하지 않는다.

## 검토·결과 기록 양식

각 Goal 작업 시 이 문서 아래에 해당 번호의 결과를 추가하거나, 필요한 경우 TODO 내 개별 기록 파일을 만들고 링크한다. 문서 수를 늘리는 것 자체를 작업으로 삼지 않는다.

```text
Goal 번호 / 작업일 / 상태:
구현 범위와 변경 파일:
참고한 Medium 버전·플랫폼·화면 ID·원본 링크:
작성하거나 수정한 테스트와 검증하는 행동:
코드 검토에서 발견한 문제와 수정 결과:
실행 명령과 결과:
Android 실행·빌드·화면 비교:
iOS 실행·빌드·화면 비교:
mock 동작과 실제 연동의 구분:
미검증 항목·남은 문제·필요한 입력:
완료 조건 충족 여부:
다음 Goal 자동 시작 여부: 시작하지 않음
```

코드 작성, 자동 테스트 통과, 기기 실행, 원본 비교를 각각 기록한다. 필요한 검증 없이 단순히 상태를 완료로 바꾸지 않는다.
