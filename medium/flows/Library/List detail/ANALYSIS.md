## 2. 플로우 목적과 연결

새 리스트의 빈 상태에서 기사 4개가 있는 목록과 스크롤 상태를 비교한다.

기사 추가 동작은 사이에 수록되지 않았다. 빈 상태와 채워진 상태를 하나의 클릭 결과로 연결하지 않는다.

- 상위 흐름: [Library](<../ANALYSIS.md>)
- 하위 흐름: [Adding a note](<Adding a note/ANALYSIS.md>) · [Removing a story](<Removing a story/ANALYSIS.md>) · [Downloading a list](<Downloading a list/ANALYSIS.md>) · [Making a list private](<Making a list private/ANALYSIS.md>) · [Reordering items](<Reordering items/ANALYSIS.md>) · [Deleting a list](<Deleting a list/ANALYSIS.md>)
- 폴더 위치: `medium/flows/Library/List detail`
- 부모·자식은 Gummble 탐색 분류다. 모든 자식 흐름이 반드시 실행되는 순차 단계나 런타임 화면 트리를 뜻하지 않는다.

### 진입 조건과 확인된 종료 범위

- 진입: 새 리스트 카드에서 빈 상세로 진입한다.
- 종료: 빈 목록 뒤 4개 글·메모 진입점·항목 메뉴가 수록된다. 글 추가 과정은 없다.
- 관련 흐름: [Creating a list](<../Creating a list/ANALYSIS.md>) · [Adding a note](<Adding a note/ANALYSIS.md>)
- 관련 흐름 링크는 기능의 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

- 입력 항목·기본값·표시 데이터: 동일 리스트 후반 항목
- 버튼·메뉴·안내 문구: Add a note, 개별 더보기
- 확인된 상태: 목록 후반
- 단계 간 변화: 내 리스트 상세 항목 → 리스트 상세 스크롤. 현재 관찰값: 동일 리스트 후반 항목. 캡처 사이의 정확한 조작·요청은 미기록이다.

#### 동작과 데이터

- 화면 관찰: 위 입력값·컨트롤·표시 상태를 확인했다. 정적 캡처이므로 실제 요청 성공·서버 영속성은 별도 증거가 필요하다.
- 공식 문서 확인: 6절에서 기능별 출처와 적용 한계를 대조한다. 이 화면의 내부 API 호출은 관찰하지 않았다.
- 설계 가정: 리스트 내 기사 순서. 구현 후보이며 확정 스키마·정책이 아니다.
- 미확인: 정렬 기준·중복 기사 허용

#### 모델링 영향

- 후보와 근거: 리스트 내 기사 순서. 위의 확인된 상태와 표시 데이터를 근거로 검토한다.
- 확정 전 확인: 정렬 기준·중복 기사 허용. 화면 관찰만으로 필수값·권한·트랜잭션을 확정하지 않는다.

기사 추가 동작은 사이에 수록되지 않았다. 빈 상태와 채워진 상태를 하나의 클릭 결과로 연결하지 않는다.

## 6. 공식 도움말과 API 대조

[공통 문서 대조](<../../../SOURCES.md#lists>).

화면에서 관찰한 값·메뉴와 문서에 없는 세부 상태는 구분한다. 미수록 오류·권한·실패 분기는 아래 질문으로 남긴다.

- [API 검토](<../../../SOURCES.md#api>). 이 흐름의 내부 endpoint·요청·응답·DB 스키마는 확인하지 않았다.
