## 2. 플로우 목적과 연결

Digest 설정에서 빈도와 푸시·이메일 채널 상태 및 이동 경로를 확인한다.

Daily·On 표시는 확인했으나 값 변경 과정은 없다. 이메일 설정과 앱 내 다이제스트 생성 주기가 같다고 확정하지 않는다.

- 상위 흐름: [Filtering digest](<../ANALYSIS.md>)
- 하위 흐름: 없음.
- 폴더 위치: `medium/flows/Library/Filtering digest/Digest settings`
- 부모·자식은 Gummble 탐색 분류다. 모든 자식 흐름이 반드시 실행되는 순차 단계나 런타임 화면 트리를 뜻하지 않는다.

### 진입 조건과 확인된 종료 범위

- 진입: Digest의 톱니바퀴에서 시작한다.
- 종료: Daily, Push On, Email On을 보여주는 설정 현황에서 기록이 끝난다.
- 관련 흐름: [Changing notification settings](<../../../Profile/Settings/Changing notification settings/ANALYSIS.md>)
- 관련 흐름 링크는 기능의 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

## 5. 업무 규칙과 데이터 변화

Daily·On 표시는 확인했으나 값 변경 과정은 없다. 이메일 설정과 앱 내 다이제스트 생성 주기가 같다고 확정하지 않는다.

| 단계 | 관찰된 상태·값 | 근거의 한계 |
| --- | --- | --- |
| 01 | 특정 날짜 다이제스트 — June 12 2025 | 화면 날짜는 캡처일이 아님·생성 기준 미확인 |
| 02 | 다이제스트 주기·알림 채널 표시 — Daily, Push On, Email On | 다른 주기 옵션·발송 시간·외부 설정 결과 미수록 |

위 표는 보이는 상태 변화다. 성공 토스트가 있어도 외부 계정의 가시성·영수증·서버 저장을 독립 검증한 것은 아니다.

## 6. 공식 도움말과 API 대조

공식 자료는 현재 문서이며 과거 캡처와 시점이 다를 수 있다. 아래 기능 설명의 범위만 대조했으며 내부 API나 제품 전체 규칙을 확인한 것은 아니다.

- [Adjust email preferences](https://help.medium.com/hc/en-us/articles/115004745947-Adjust-email-preferences): 이메일 알림 종류와 Digest 주기 설정을 설명한다. 앱의 푸시 토글 전체 계약을 대신하지 않는다. [공통 문서 대조](<../../../../SOURCES.md#email>).

공식 이메일 설정과 캡처의 앱 Digest 설정은 진입점이 다르다. 두 주기가 같은 저장값인지와 푸시 옵션 계약은 미확인이다.

- [API 검토](<../../../../SOURCES.md#api>). 이 흐름의 내부 endpoint·요청·응답·DB 스키마는 확인하지 않았다.
