## 2. 플로우 목적과 연결

본인 응답 메뉴의 Delete response와 삭제 성공 토스트·목록 제거를 확인한다.

별도 확인 대화상자는 수록되지 않았다. 답글이 있는 응답의 삭제 영향과 복구는 추가 검증 대상이다.

- 상위 흐름: [Commenting a story](<../ANALYSIS.md>)
- 하위 흐름: 없음.
- 폴더 위치: `medium/flows/Home/Story detail/Responses/Commenting a story/Deleting a response`
- 부모·자식은 Gummble 탐색 분류다. 모든 자식 흐름이 반드시 실행되는 순차 단계나 런타임 화면 트리를 뜻하지 않는다.

### 진입 조건과 확인된 종료 범위

- 진입: YOU 응답의 Delete response 메뉴에서 시작한다.
- 종료: 본인 응답이 사라지고 삭제 성공 토스트가 보인다. 총수는 토스트에 가린다.
- 관련 흐름: [Commenting a story](<../ANALYSIS.md>)
- 관련 흐름 링크는 기능의 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

공식 자료는 현재 문서이며 과거 캡처와 시점이 다를 수 있다. 아래 기능 설명의 범위만 대조했으며 내부 API나 제품 전체 규칙을 확인한 것은 아니다.

- [Write a response](https://help.medium.com/hc/en-us/articles/214578008-Write-a-response): 응답에는 로그인이 필요하고 특정 구절을 인용할 수 있다. 수정·삭제·정렬의 세부 계약은 이 문서로 확정하지 않는다. [공통 문서 대조](<../../../../../../SOURCES.md#responses>).
- [Manage responses](https://help.medium.com/hc/en-us/articles/217048127-Manage-responses): 글·리스트 소유자는 응답 숨김과 토론 닫기를 관리할 수 있다. 현재 도움말에서 토론 닫기는 새 응답 작성과 기존 응답 수정을 막되 기존 응답은 남긴다. 이는 댓글 작성자의 자기 응답 삭제와 다른 동작이며, 이번 캡처에는 소유자의 관리 화면·닫힌 토론 상태가 없다. [공통 문서 대조](<../../../../../../SOURCES.md#moderation>).

응답 도움말은 작성 기능의 배경 자료다. 삭제 복구와 자식 답글 처리 계약은 별도 확인 대상이다.

- [API 검토](<../../../../../../SOURCES.md#api>). 이 흐름의 내부 endpoint·요청·응답·DB 스키마는 확인하지 않았다.

## 7. 데이터 모델링 시사점

다음은 관찰에 기반한 구현 후보다. Kostolany의 기능 채택·스키마·업무 정책으로 확정하지 않는다.

- 단계 01: 응답 생성 후 목록·집계 갱신
- 단계 02: 작성자별 관리 권한
- 단계 03: 삭제 결과와 부모·자식 처리 정책

## 8. 미확인 사항과 검토 질문

**원본에 없는 분기·남은 범위:** 삭제 전 확인·취소·복구·답글 연쇄 처리·재진입, 서버 소유권 검증.

- 단계 01: 서버 생성·다른 사용자 가시성
- 단계 02: 타인 메뉴·서버 소유권 검증
- 단계 03: 삭제 확인 단계·복구·자식 답글 영향 미수록
- 같은 계정·같은 빌드에서 시작 상태를 맞춘 뒤 정상·취소·실패·재진입 결과를 검증해야 한다.
