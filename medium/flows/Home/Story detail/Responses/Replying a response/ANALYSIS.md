## 2. 플로우 목적과 연결

특정 응답을 대상으로 지정하고 Agree!를 작성하여 하위 답글로 표시하는 흐름을 분석한다.

832 총수가 생성 후에도 유지된다. 답글을 제외하는 집계인지 갱신 지연인지 단정하지 않는다.

- 상위 흐름: [Responses](<../ANALYSIS.md>)
- 하위 흐름: 없음.
- 폴더 위치: `medium/flows/Home/Story detail/Responses/Replying a response`
- 부모·자식은 Gummble 탐색 분류다. 모든 자식 흐름이 반드시 실행되는 순차 단계나 런타임 화면 트리를 뜻하지 않는다.

### 진입 조건과 확인된 종료 범위

- 진입: 기존 응답에 Reply를 선택한 상태가 수록된다.
- 종료: Replying to Bérnie 입력 뒤 Agree!가 YOU 답글로 나타난다. 총수 832는 유지된다.
- 관련 흐름: [Commenting a story](<../Commenting a story/ANALYSIS.md>)
- 관련 흐름 링크는 기능의 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

- 공식 문서 확인: 6절에서 기능별 출처와 적용 한계를 대조한다. 이 화면의 내부 API 호출은 관찰하지 않았다.
- 설계 가정: 답글 수와 상위 응답 수 집계 분리 검증. 구현 후보이며 확정 스키마·정책이 아니다.
- 미확인: 총수 미변화가 집계 규칙인지 갱신 지연인지 미확인

#### 모델링 영향

- 후보와 근거: 답글 수와 상위 응답 수 집계 분리 검증. 위의 확인된 상태와 표시 데이터를 근거로 검토한다.
- 확정 전 확인: 총수 미변화가 집계 규칙인지 갱신 지연인지 미확인. 화면 관찰만으로 필수값·권한·트랜잭션을 확정하지 않는다.

## 6. 공식 도움말과 API 대조

공식 자료는 현재 문서이며 과거 캡처와 시점이 다를 수 있다. 아래 기능 설명의 범위만 대조했으며 내부 API나 제품 전체 규칙을 확인한 것은 아니다.

- [Write a response](https://help.medium.com/hc/en-us/articles/214578008-Write-a-response): 응답에는 로그인이 필요하고 특정 구절을 인용할 수 있다. 수정·삭제·정렬의 세부 계약은 이 문서로 확정하지 않는다. [공통 문서 대조](<../../../../../SOURCES.md#responses>).
- [Manage responses](https://help.medium.com/hc/en-us/articles/217048127-Manage-responses): 글·리스트 소유자는 응답 숨김과 토론 닫기를 관리할 수 있다. 현재 도움말에서 토론 닫기는 새 응답 작성과 기존 응답 수정을 막되 기존 응답은 남긴다. 이는 댓글 작성자의 자기 응답 삭제와 다른 동작이며, 이번 캡처에는 소유자의 관리 화면·닫힌 토론 상태가 없다. [공통 문서 대조](<../../../../../SOURCES.md#moderation>).

화면에서 관찰한 값·메뉴와 문서에 없는 세부 상태는 구분한다. 미수록 오류·권한·실패 분기는 아래 질문으로 남긴다.

- [API 검토](<../../../../../SOURCES.md#api>). 이 흐름의 내부 endpoint·요청·응답·DB 스키마는 확인하지 않았다.
