## 2. 플로우 목적과 연결

세로 속도 조절에서 1x를 2.5x로 바꾸고 플레이어 표기를 확인한다.

WPM과 생산성 안내는 화면 표시값이다. 재생 위치가 달라진 원인과 정확한 시간 환산식은 미확인이다.

- 상위 흐름: [Listening to a story](<../ANALYSIS.md>)
- 하위 흐름: 없음.
- 폴더 위치: `medium/flows/Home/Story detail/Listening to a story/Changing playback speed`
- 부모·자식은 Gummble 탐색 분류다. 모든 자식 흐름이 반드시 실행되는 순차 단계나 런타임 화면 트리를 뜻하지 않는다.

### 진입 조건과 확인된 종료 범위

- 진입: 확장 플레이어의 1x 상태에서 시작한다.
- 종료: 1x/200 WPM에서 2.5x/490 WPM으로 선택한 뒤 플레이어에 2.5x가 표시된다.
- 관련 흐름: [Listening to a story](<../ANALYSIS.md>)
- 관련 흐름 링크는 기능의 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

- 단계 간 변화: 재생 속도 2.5배 선택 → 2.5배 재생 표시. 현재 관찰값: 2.5x, 00:10, -01:44. 캡처 사이의 정확한 조작·요청은 미기록이다.

#### 동작과 데이터

- 화면 관찰: 위 입력값·컨트롤·표시 상태를 확인했다. 정적 캡처이므로 실제 요청 성공·서버 영속성은 별도 증거가 필요하다.
- 공식 문서 확인: 6절에서 기능별 출처와 적용 한계를 대조한다. 이 화면의 내부 API 호출은 관찰하지 않았다.
- 설계 가정: 원문 위치와 배속 환산 시간 분리. 구현 후보이며 확정 스키마·정책이 아니다.
- 미확인: 남은 시간 계산·위치 재설정 원인

#### 모델링 영향

- 후보와 근거: 원문 위치와 배속 환산 시간 분리. 위의 확인된 상태와 표시 데이터를 근거로 검토한다.
- 확정 전 확인: 남은 시간 계산·위치 재설정 원인. 화면 관찰만으로 필수값·권한·트랜잭션을 확정하지 않는다.

## 5. 업무 규칙과 데이터 변화

WPM과 생산성 안내는 화면 표시값이다. 재생 위치가 달라진 원인과 정확한 시간 환산식은 미확인이다.

| 단계 | 관찰된 상태·값 | 근거의 한계 |
| --- | --- | --- |
| 01 | 확장 재생 화면 — 00:05, -04:35, 1x | 음원 실제 길이·탐색·다음 기사 조건 |
| 02 | 현재 속도 표시 — 1x, 200 WPM | 최소·최대·증분·WPM 계산 |
| 03 | 변경값 표시 — 2.5x, 490 WPM, 145% productivity boost | 안내 수치 근거·즉시 적용 여부 |

위 표는 보이는 상태 변화다. 성공 토스트가 있어도 외부 계정의 가시성·영수증·서버 저장을 독립 검증한 것은 아니다.
