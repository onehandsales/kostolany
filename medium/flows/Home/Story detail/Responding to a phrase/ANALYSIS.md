## 2. 플로우 목적과 연결

선택 구절을 인용 카드로 붙여 응답을 작성·등록하는 흐름을 분석한다.

인용 원문과 작성 응답이 별도로 보인다. 원문 수정 후 앵커 유지나 전체 응답 수 갱신은 미확인이다.

- 상위 흐름: [Story detail](<../ANALYSIS.md>)
- 하위 흐름: 없음.
- 폴더 위치: `medium/flows/Home/Story detail/Responding to a phrase`
- 부모·자식은 Gummble 탐색 분류다. 모든 자식 흐름이 반드시 실행되는 순차 단계나 런타임 화면 트리를 뜻하지 않는다.

### 진입 조건과 확인된 종료 범위

- 진입: 본문 선택 메뉴의 Respond 분기다.
- 종료: 빈 본문에서는 회색 전송, 입력 뒤 검은 전송, 결과에는 인용과 YOU 응답이 함께 표시된다.
- 관련 흐름: [Commenting a story](<../Responses/Commenting a story/ANALYSIS.md>) · [Highlighting a phrase](<../Highlighting a phrase/ANALYSIS.md>)
- 관련 흐름 링크는 기능의 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

- R2 보완 관찰·해석: 인용 블록과 본인 응답이 함께 나타나지만 총수 834는 입력 전후 동일하다. 등록 성공 UI와 총수 집계 규칙을 분리하고, 단순히 +1이어야 한다고 교정하지 않는다.
- 단계 간 변화: 구절 응답 입력 → 구절 인용 응답 등록. 현재 관찰값: Now, 총수 834 유지. 캡처 사이의 정확한 조작·요청은 미기록이다.

#### 동작과 데이터

- 화면 관찰: 위 입력값·컨트롤·표시 상태를 확인했다. 정적 캡처이므로 실제 요청 성공·서버 영속성은 별도 증거가 필요하다.
- 공식 문서 확인: 6절에서 기능별 출처와 적용 한계를 대조한다. 이 화면의 내부 API 호출은 관찰하지 않았다.
- 설계 가정: 인용 응답과 일반 응답의 공통·선택 필드. 구현 후보이며 확정 스키마·정책이 아니다.
- 미확인: 총수 갱신·원문 이동 동작

#### 모델링 영향

- 후보와 근거: 인용 응답과 일반 응답의 공통·선택 필드. 위의 확인된 상태와 표시 데이터를 근거로 검토한다.
- 확정 전 확인: 총수 갱신·원문 이동 동작. 화면 관찰만으로 필수값·권한·트랜잭션을 확정하지 않는다.

## 5. 업무 규칙과 데이터 변화

인용 원문과 작성 응답이 별도로 보인다. 원문 수정 후 앵커 유지나 전체 응답 수 갱신은 미확인이다.

| 단계 | 관찰된 상태·값 | 근거의 한계 |
| --- | --- | --- |
| 01 | 텍스트 선택 상태 — 여러 줄 텍스트 선택 | 선택 앵커·문서 수정 후 범위 복원 |
| 02 | 인용 포함 응답 초안 — 인용 문구 자동 포함, 본문 빈값 | 인용 길이·편집·원문 연결 방식 |
| 03 | 인용 응답 제출 준비 — Can't agree more! | 입력 제한·인용 삭제 가능 여부 |
| 04 | 인용 응답 목록에 표시 — Now, 총수 834 유지 | 총수 갱신·원문 이동 동작 |

위 표는 보이는 상태 변화다. 성공 토스트가 있어도 외부 계정의 가시성·영수증·서버 저장을 독립 검증한 것은 아니다.
