## 2. 플로우 목적과 연결

본문 구절 선택과 Highlight 이후 강조 유지 상태를 확인한다.

본문의 기존 강조와 새로 선택한 강조를 구분한다. 강조 공개 범위는 공식 설명과 대조한다.

- 상위 흐름: [Story detail](<../ANALYSIS.md>)
- 하위 흐름: 없음.
- 폴더 위치: `medium/flows/Home/Story detail/Highlighting a phrase`
- 부모·자식은 Gummble 탐색 분류다. 모든 자식 흐름이 반드시 실행되는 순차 단계나 런타임 화면 트리를 뜻하지 않는다.

### 진입 조건과 확인된 종료 범위

- 진입: 본문의 선택 가능한 텍스트에서 시작한다.
- 종료: 선택 핸들·Highlight 메뉴 뒤 구절의 녹색 강조가 남는다.
- 관련 흐름: [Responding to a phrase](<../Responding to a phrase/ANALYSIS.md>) · [Library](<../../../Library/ANALYSIS.md>)
- 관련 흐름 링크는 기능의 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

## 5. 업무 규칙과 데이터 변화

본문의 기존 강조와 새로 선택한 강조를 구분한다. 강조 공개 범위는 공식 설명과 대조한다.

| 단계 | 관찰된 상태·값 | 근거의 한계 |
| --- | --- | --- |
| 01 | 본문 중간 읽기 — 여러 텍스트 강조 범위 | 강조가 개인 것인지 인기 강조인지 화면만으로 미확인 |

| 03 | 하이라이트 적용 표시 — 선택했던 구절 강조 | 타 기기 동기화·삭제·공개 범위 |

위 표는 보이는 상태 변화다. 성공 토스트가 있어도 외부 계정의 가시성·영수증·서버 저장을 독립 검증한 것은 아니다.

## 6. 공식 도움말과 API 대조

공식 자료는 현재 문서이며 과거 캡처와 시점이 다를 수 있다. 아래 기능 설명의 범위만 대조했으며 내부 API나 제품 전체 규칙을 확인한 것은 아니다.

- [About highlights](https://help.medium.com/hc/en-us/articles/214406358-About-highlights): 강조 구절은 작성자·팔로워에게 보일 수 있다. 구절 인용 응답과 타인 하이라이트 숨김을 설명한다. [공통 문서 대조](<../../../../SOURCES.md#highlights>).

화면에서 관찰한 값·메뉴와 문서에 없는 세부 상태는 구분한다. 미수록 오류·권한·실패 분기는 아래 질문으로 남긴다.

## 7. 데이터 모델링 시사점

다음은 관찰에 기반한 구현 후보다. Kostolany의 기능 채택·스키마·업무 정책으로 확정하지 않는다.

- 단계 01: 본문 위치와 강조 범위 별도 관리
- 단계 02: 구절 시작·끝과 인용 텍스트 저장 후보
- 단계 03: 사용자 강조와 텍스트 범위

## 8. 미확인 사항과 검토 질문

**원본에 없는 분기·남은 범위:** 강조 제거·겹침·원문 수정/삭제·동기화·타인 노출, Share/더보기 실행.

- 단계 01: 강조가 개인 것인지 인기 강조인지 화면만으로 미확인
- 단계 02: 선택 앵커·문서 수정 후 범위 복원
- 단계 03: 타 기기 동기화·삭제·공개 범위
- 같은 계정·같은 빌드에서 시작 상태를 맞춘 뒤 정상·취소·실패·재진입 결과를 검증해야 한다.
