## 2. 플로우 목적과 연결

기사 작성자에서 프로필 Stories·Lists·About를 탐색하는 구조를 분석한다.

기사 말미 following 24와 프로필 25가 다르다. 조회 시점·데이터 차이를 단일 변경 이벤트로 설명하지 않는다.

- 상위 흐름: [Story detail](<../ANALYSIS.md>)
- 하위 흐름: [Following list](<Following list/ANALYSIS.md>) · [Following an author](<Following an author/ANALYSIS.md>) · [Muting an author](<Muting an author/ANALYSIS.md>) · [Blocking an author](<Blocking an author/ANALYSIS.md>) · [Reporting an author](<Reporting an author/ANALYSIS.md>)
- 폴더 위치: `medium/flows/Home/Story detail/Author detail`
- 부모·자식은 Gummble 탐색 분류다. 모든 자식 흐름이 반드시 실행되는 순차 단계나 런타임 화면 트리를 뜻하지 않는다.

### 진입 조건과 확인된 종료 범위

- 진입: 기사의 작가 정보에서 프로필로 연결된다.
- 종료: Stories의 고정 글, Lists, About과 회원 시작 월을 비교한다.
- 관련 흐름: [Following list](<Following list/ANALYSIS.md>) · [Profile](<../../../Profile/ANALYSIS.md>)
- 관련 흐름 링크는 기능의 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

- R2 보완 관찰·해석: 일반 멤버 시작 월과 Friend 시작 월은 별도로 표시된다. 계정 최초 생성일·과거 결제 내역을 이 두 날짜에서 역산하지 않는다.
- 단계 간 변화: 작가 공개 리스트 → 작가 About. 현재 관찰값: Medium member since October 2023, Friend since December 2023. 캡처 사이의 정확한 조작·요청은 미기록이다.

#### 동작과 데이터

- 화면 관찰: 위 입력값·컨트롤·표시 상태를 확인했다. 정적 캡처이므로 실제 요청 성공·서버 영속성은 별도 증거가 필요하다.
- 공식 문서 확인: 6절에서 기능별 출처와 적용 한계를 대조한다. 이 화면의 내부 API 호출은 관찰하지 않았다.
- 설계 가정: 프로필 소개와 구독 이력 공개값. 구현 후보이며 확정 스키마·정책이 아니다.
- 미확인: 작성 가능한 소개 형식·이력 공개 조건

#### 모델링 영향

- 후보와 근거: 프로필 소개와 구독 이력 공개값. 위의 확인된 상태와 표시 데이터를 근거로 검토한다.
- 확정 전 확인: 작성 가능한 소개 형식·이력 공개 조건. 화면 관찰만으로 필수값·권한·트랜잭션을 확정하지 않는다.

## 5. 업무 규칙과 데이터 변화

기사 말미 following 24와 프로필 25가 다르다. 조회 시점·데이터 차이를 단일 변경 이벤트로 설명하지 않는다.

| 단계 | 관찰된 상태·값 | 근거의 한계 |
| --- | --- | --- |
| 01 | 멤버 전용 기사 읽기 화면 — 5 min read, Apr 30 2025, Jordan Gibbs, 18K 박수·834 응답 | 현재 계정 권한·본문 게이트·집계 정확값 |
| 02 | 고정 글 Pinned 표시 — Jordan Gibbs, 10.2K followers·25 following | 프로필 내 정렬·배지 현재 조건 |
| 03 | 작가 목록 탐색 — 2 stories·이미지 모음 | 비공개 리스트 누락 범위 |
| 04 | 소개·회원 이력 표시 — Medium member since October 2023, Friend since December 2023 | 작성 가능한 소개 형식·이력 공개 조건 |

위 표는 보이는 상태 변화다. 성공 토스트가 있어도 외부 계정의 가시성·영수증·서버 저장을 독립 검증한 것은 아니다.

## 6. 공식 도움말과 API 대조

공식 자료는 현재 문서이며 과거 캡처와 시점이 다를 수 있다. 아래 기능 설명의 범위만 대조했으며 내부 API나 제품 전체 규칙을 확인한 것은 아니다.

- [Your profile page](https://help.medium.com/hc/en-us/articles/115004747067-Your-profile-page): 앱에서 이름·사진·160자 소개를 수정한다. 더 긴 About 편집은 웹에서 제공한다. [공통 문서 대조](<../../../../SOURCES.md#profile>).
- [Follow writers and publications](https://help.medium.com/hc/en-us/articles/35754720183063-Follow-writers-and-publications): 팔로우와 작가별 이메일 알림 선택을 설명한다. 알림 발송에는 작가의 발송 선택도 관여한다. [공통 문서 대조](<../../../../SOURCES.md#follow>).

화면에서 관찰한 값·메뉴와 문서에 없는 세부 상태는 구분한다. 미수록 오류·권한·실패 분기는 아래 질문으로 남긴다.

- [API 검토](<../../../../SOURCES.md#api>). 이 흐름의 내부 endpoint·요청·응답·DB 스키마는 확인하지 않았다.
